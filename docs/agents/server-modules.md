# 服务端模块地图（导航）

`server/lautung-oa-parent/` 是多模块 Maven 工程（扁平 `lautung-oa-*` 模块，groupId `com.lautung`）。找服务端的东西先看这张表，再决定要不要 grep。
客户端模块与审批端口见 `client-modules.md`；领域术语见根目录 `GLOSSARY.md`。

模块依赖边（无环）：`common ← framework`；`common, model ← security`；`common, framework, security, model ← audit`；`common, framework, security, model ← auth`；`common, framework, security, model, auth ← process`；全部 ← `server`。业务代码包声明为 `com.lautung.oa.*`；Flyway Java 迁移固定在 `db.migration`（不在 `com.lautung.oa` 树下，也不在 ArchUnit 分析集内）。

## 认证与错误语义（改安全相关代码前必读）

请求经过的层，顺序即拒绝优先级：

1. `TokenAuthenticationFilter`：`PublicApiPaths.permitsAnonymous(uri)` 的 URI 跳过校验；其余请求无有效 token → **401 + code 208**；停用账号 → 401 + 209。四连核验（吊销/身份/版本/停用）由 `SessionVerifier` 承担（ADR 0044），过滤器与续期端点共用同一实现。
2. `TokenLoginFilter`：只接 `POST /admin/system/index/login`（POST-only 且不在白名单里，靠过滤器先于授权层接管）。空凭证/畸形体在限流计数之前拒绝（**401 + 208 + 字段消息**，不计入失败次数）；登录失败/锁定/停用 → **401 + 208/209**。
3. `AuthorizationFilter`：白名单 `permitAll`，其余 `authenticated()`。未认证被拒 → `RestAuthenticationEntryPoint`（**401 + 208**，覆盖匿名路径上的错误方法）；已认证被拒 → `RestAccessDeniedHandler`（**403 + 205**）。
4. `IndexController.refresh`：匿名白名单上的续期端点，失败由控制器自己写出认证家族语义（ADR 0037）——缺失/空白/无效/吊销的 refreshToken **401 + 208「认证失败」**，停用用户 **401 + 209**；畸形 JSON 仍按第 6 条的 200+201。
5. MVC 参数解析：`@Valid` 在控制器方法调用前执行，所以**校验先于 `@PreAuthorize`**。未授权 + 畸形体得到校验失败（201），不是 205；良构体才轮到后台 gate。认证早于这一层，所以受保护路由上匿名 + 畸形体仍是 401+208（ADR 0034）。
6. `@PreAuthorize`：拒绝 → `GlobalExceptionHandler` 的 `AccessDeniedException` 分支（**HTTP 200 + code 205**，历史约定）。未知路径 404、方法不匹配 405（均带 `code=201` 信封）；校验失败与缺体/畸形 JSON 是 HTTP 200 + `code=201` + 具体消息（ADR 0033）；其余业务失败 HTTP 200 + `code`。

回归锚点：`LoginAuthContractTest`（401/208/209 全表，含 refresh 失败形状与缺失/空白/无体）、`LoginLogContractTest`（登录成功/失败/锁定/解锁/停用落库、锁定期尝试不落库、UA 解析与 username 截断、DB 故障仍可登录）、`HttpErrorSemanticsContractTest`（404/405/类型不匹配）、`RequestValidationContractTest`（参数校验 201 文案与顺序契约）、`BackofficeRouteAuthorizationContractTest`（页面/按钮 gate、写端点必须声明按钮点、`/info` 合同）、`BackofficeGrantTest`（页面/按钮/隐藏页授予矩阵）、`RolePermissionMaintenanceContractTest`（角色数据范围五档与自定部门回读、按钮授予往返 `/info.permissions`、隐藏页单独授予不落库、按钮 perms 唯一）、`DataScopeContractTest`（五档 × 单/多角色并集、无角色、无部门、部门被删，用户列表与审批实例查询的空集必须零行）、`FlywayMigrationContractTest`（迁移与 `/info` 种子，用良构体触发）、`OperLogCoverageTest`（后台写方法漏注解即红）、`OperLogContractTest`（一条真实写请求一行、参数打码、`create_time` 已填、205/201 零行）、`OperLogQueryContractTest`（分页形状与 `create_time DESC, id DESC`、各过滤条件、详情、批量删除/空列表 201、清空与清空行存活、三种数据范围形状、范围外详情不泄漏）、`LoginLogQueryContractTest`（分页与排序、各过滤条件、批量删除/空列表 201、清空、三种数据范围形状含未知用户行只在 unrestricted 可见、解锁清账号维度键并双写两表、缺按钮点 205）、接口套件 `tests/api/f-http-semantics.spec.ts`、`tests/api/b-menu.spec.ts`（B22 顺序契约）、`tests/api/g-audit.spec.ts`（操作日志与登录日志端点、按钮点 205、解锁双写）。改本节描述的认证/校验优先级/错误语义家族（security 链、`@PreAuthorize`/`backofficeGate`、201/205/208/209）的轮次，附带重跑安全扫描（`node scripts/security-scan.mjs`，打在跑的演示栈）并当轮定性红项——SEC-GATE 系载荷对这类改动敏感，陈旧红靠周检才发现就太迟（#184）。

## 行政约定

- 后台写动作（`/admin/system/*` 的 POST/PUT/DELETE）必须挂 `@OperLog(title, businessType)`，标题用「模块·动作」形状；登录/续期/退出与办事/审批写动作不记（`oa_process_record` 是审批动作账本，ADR 0049/0054）。漏挂由 `OperLogCoverageTest` 反射扫描钉红；`IndexController` 显式排除。审计行写入时快照操作人姓名与部门，不 join 用户/菜单。日志管理自身的删除/清空/解锁也各记一行（「操作日志·删除」/「操作日志·清空」/「登录日志·解锁」）；清空行在方法返回后写入，所以不会被同一次清空删掉。登录日志的解锁还由限流端口写一条 `status=3` 行——两表用途不同，双写。
- 业务 `@RequestMapping` 前缀：`/admin/system/*`（认证与配置）、`/admin/process/*`（流程）、`/admin/attachments/*`。
- 静态形状约束写请求 DTO 的 jsr303 注解 + `@Valid`；领域/状态判断留 service；登录在 `TokenLoginFilter` 里手工校验（ADR 0033）；refresh 的失败按认证家族由控制器写 401（ADR 0037），不走 201 校验路线。
- 配置类写请求体是 `model` 的 `vo/{system,process}/XxxRequest`：save 只创建（不含 `id`）、update 只要求 `id`、其余为空即不覆盖；改这两条规则先看 ADR 0034。长度上限对齐列宽、`sys_menu.type` 收 0/1/2（按钮点 perms 必填且非删除行内唯一、path/component 为空、父级必须是页面；save 在 DTO，父级/落库形状/唯一性在 service 判），见 ADR 0036/0056。角色写请求的 `dataScope` 1..5 与 `deptIds` 按最终落库形状同步 `sys_role_dept`：save 缺省 5、scope=2 必填部门；update 空字段保留、显式 `deptIds`（含空列表）替换、非 2 档清空。`GET /admin/system/sysRole/depts` 是数据范围选择器的只读部门选项（启用且未删除），不提供部门 CRUD。
- 审批页面挂在 `/system` 下：目录 `processSet`/`processMgr`，页面绝对路径 `/system/processSet/...`、`/system/processMgr/...`；14 个 process gate 字面量已随之改为绝对路径。
- 后台接口由 `@backofficeGate.isAllowed('<页面绝对路径>'[, '<权限标识>'])` 统一判定（ADR 0052/0056）：读端点只传页面，写端点再传 V110 按钮点；页面先、按钮后，拒绝都是 HTTP 200 + code 205「没有操作权限」。`sys_menu` 全表即后台（type 0/1/2），没有根白名单与旧组件排除；隐藏页不单独构成权限，也不作 gate 目标。
- 数据范围（ADR 0053/0057）由 `DataScopeResolver`（security 端口 `DataScopeProvider`）每请求解析成 `DataScope` 值对象，查询侧只接参数：MP wrapper 的 `in`/`or`，手写 XML 的 `#{}` + `<foreach>`，**禁止 `${}` 片段展开**。接入点：用户列表（部门列 `sys_user.dept_id`、本人列 `sys_user.id`）、操作日志（部门列 `sys_oper_log.dept_id`、本人列 `oper_id`）、登录日志（部门列 `sys_login_log.dept_id`、本人列 `user_id`）与审批实例查询（部门列 = 发起人部门 `d.dept_id`、本人列 = 发起人 `a.user_id`）；办事四种列表、审批详情、部门/岗位/菜单/角色/配置/公告/监控都不套。部门集为空且无本人行（且不是 `unrestricted`）时是**零行**，不是全部；日志的删除/清空/解锁是 gate-only，不套范围；解析器不缓存、不进 `/info`。
- 后台页面路径一律绝对：`/system/processSet/...`、`/system/processMgr/...`（#221）、`/system/sysUser`、`/system/sysRole`、`/system/sysMenu`、`/system/assignAuth`（V111，#222）、`/system/log/operLog`（V113，#214）与 `/system/log/loginLog`（V115，#216；两者共用目录 `log`）。`/info` 返回 `{name, avatar, roles[], permissions[], menus[]}`，`menus` 只含 type 0/1（`path`/`parentPath`/`title`/`type`/`hidden`/`sort`/`icon`），按钮点只进 `permissions`（ADR 0058）。
- 表结构迁移只加不改：`lautung-oa-server/src/main/resources/db/migration/V*.sql`，Flyway 按版本执行。
- `POST /admin/process/startUp` 的 `idempotencyKey` 可空，唯一索引 `uk_oa_process_idempotency_key` 按用户唯一（ADR 0032）：重复送达返回同一条审批；冲突后的重读必须在 `ApprovalWriter.startUp` 的事务之外（可重复读下事务内看不到对手已提交的行）。
