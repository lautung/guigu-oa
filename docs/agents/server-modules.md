# 服务端模块地图（导航）

`server/lautung-oa-parent/` 是多模块 Maven 工程（扁平 `lautung-oa-*` 模块，groupId `com.lautung`）。找服务端的东西先看这张表，再决定要不要 grep。
客户端模块与审批端口见 `client-modules.md`；领域术语见根目录 `GLOSSARY.md`。

模块依赖边（无环）：`common ← framework`；`common, model ← security`；`common ← storage`；`common, framework, security, model ← audit`；`common, framework, security, model ← auth`；`common, framework, security, model, storage ← notice`；`common, framework, security, model, auth, storage ← process`；`common, framework, security, model ← monitor`；`common, framework, security, model ← dict`；`common, framework, security, model ← config`；`common, framework, security, model, config ← auth`（注册开关由 auth 读 config 端口，#253 已落地）；全部 ← `server`。业务代码包声明为 `com.lautung.oa.*`；Flyway Java 迁移固定在 `db.migration`（不在 `com.lautung.oa` 树下，也不在 ArchUnit 分析集内）。

端口/域的值对象与读模型放 `lautung-oa-model`（先例 `DataScope`、`OnlineSession`/`SessionTime`）；页面 VO 的映射留在消费域，跨域端口不 import 别的域的 VO（本域产出的协议响应如 `LoginVo` 除外）。

## 认证与错误语义（改安全相关代码前必读）

请求经过的层，顺序即拒绝优先级：

1. `TokenAuthenticationFilter`：`PublicApiPaths.permitsAnonymous(uri)` 的 URI 跳过校验；其余请求无有效 token → **401 + code 208**；停用账号 → 401 + 209。四连核验（吊销/身份/版本/停用）由 `SessionVerifier` 承担（ADR 0044），过滤器与续期端点共用同一实现。
2. `TokenLoginFilter`：只接 `POST /admin/system/index/login`（POST-only 且不在白名单里，靠过滤器先于授权层接管）。空凭证/畸形体在限流计数之前拒绝（**401 + 208 + 字段消息**，不计入失败次数）；登录失败/锁定/停用 → **401 + 208/209**。
3. `AuthorizationFilter`：白名单 `permitAll`，其余 `authenticated()`。未认证被拒 → `RestAuthenticationEntryPoint`（**401 + 208**，覆盖匿名路径上的错误方法）；已认证被拒 → `RestAccessDeniedHandler`（**403 + 205**）。
4. `IndexController.refresh`：匿名白名单上的续期端点，失败由控制器自己写出认证家族语义（ADR 0037）——缺失/空白/无效/吊销的 refreshToken **401 + 208「认证失败」**，停用用户 **401 + 209**；畸形 JSON 仍按第 6 条的 200+201。
5. MVC 参数解析：`@Valid` 在控制器方法调用前执行，所以**校验先于 `@PreAuthorize`**。未授权 + 畸形体得到校验失败（201），不是 205；良构体才轮到后台 gate。认证早于这一层，所以受保护路由上匿名 + 畸形体仍是 401+208（ADR 0034）。
6. `@PreAuthorize`：拒绝 → `GlobalExceptionHandler` 的 `AccessDeniedException` 分支（**HTTP 200 + code 205**，历史约定）。未知路径 404、方法不匹配 405（均带 `code=201` 信封）；校验失败与缺体/畸形 JSON 是 HTTP 200 + `code=201` + 具体消息（ADR 0033）；其余业务失败 HTTP 200 + `code`。

## 行政约定

- 后台写动作（`/admin/system/*` 与 `/admin/monitor/*` 的 POST/PUT/DELETE）必须挂 `@OperLog(title, businessType)`，标题用「模块·动作」形状；登录/续期/退出与办事/审批写动作不记（`oa_process_record` 是审批动作账本，ADR 0049/0054）。漏挂由 `OperLogCoverageTest` 反射扫描钉红；`IndexController` 显式排除。审计行写入时快照操作人姓名与部门，不 join 用户/菜单。日志管理自身的删除/清空/解锁也各记一行（「操作日志·删除」/「操作日志·清空」/「登录日志·解锁」）；清空行在方法返回后写入，所以不会被同一次清空删掉。登录日志的解锁还由限流端口写一条 `status=3` 行——两表用途不同，双写。缓存列表的两个清理动作各记一行（「缓存列表·删除键」/「缓存列表·清空权限缓存」，#237）。
- 业务 `@RequestMapping` 前缀：`/admin/system/*`（认证与配置）、`/admin/process/*`（流程）、`/admin/attachments/*`、`/admin/notices/*`（公告内置读面；写面在 `/admin/system/notices/*`）、`/admin/monitor/*`（监控：在线用户等，ADR 0060）。
- 静态形状约束写请求 DTO 的 jsr303 注解 + `@Valid`；领域/状态判断留 service；登录在 `TokenLoginFilter` 里手工校验（ADR 0033）；refresh 的失败按认证家族由控制器写 401（ADR 0037），不走 201 校验路线。
- 配置类写请求体是 `model` 的 `vo/{system,process}/XxxRequest`：save 只创建（不含 `id`）、update 只要求 `id`、其余为空即不覆盖；改这两条规则先看 ADR 0034。长度上限对齐列宽、`sys_menu.type` 收 0/1/2（按钮点 perms 必填且非删除行内唯一、path/component 为空、父级必须是页面；save 在 DTO，父级/落库形状/唯一性在 service 判），见 ADR 0036/0056。角色写请求的 `dataScope` 1..5 与 `deptIds` 按最终落库形状同步 `sys_role_dept`：save 缺省 5、scope=2 必填部门；update 空字段保留、显式 `deptIds`（含空列表）替换、非 2 档清空。`GET /admin/system/sysRole/depts` 是数据范围选择器的只读部门选项（启用且未删除），不提供部门 CRUD。
- 审批页面挂在 `/system` 下：目录 `processSet`/`processMgr`，页面绝对路径 `/system/processSet/...`、`/system/processMgr/...`；14 个 process gate 字面量已随之改为绝对路径。
- 后台接口由 `@backofficeGate.isAllowed('<页面绝对路径>'[, '<权限标识>'])` 统一判定（ADR 0052/0056）：读端点只传页面，写端点再传 V110 按钮点；页面先、按钮后，拒绝都是 HTTP 200 + code 205「没有操作权限」。`sys_menu` 全表即后台（type 0/1/2），没有根白名单与旧组件排除；隐藏页不单独构成权限，也不作 gate 目标。
- 数据范围（ADR 0053/0057）由 `DataScopeResolver`（security 端口 `DataScopeProvider`）每请求解析成 `DataScope` 值对象，查询侧只接参数：MP wrapper 的 `in`/`or`，手写 XML 的 `#{}` + `<foreach>`，**禁止 `${}` 片段展开**。接入点：用户列表（部门列 `sys_user.dept_id`、本人列 `sys_user.id`）、操作日志（部门列 `sys_oper_log.dept_id`、本人列 `oper_id`）、登录日志（部门列 `sys_login_log.dept_id`、本人列 `user_id`）与审批实例查询（部门列 = 发起人部门 `d.dept_id`、本人列 = 发起人 `a.user_id`）；办事四种列表、审批详情、部门/岗位/菜单/角色/配置/公告/监控都不套。部门集为空且无本人行（且不是 `unrestricted`）时是**零行**，不是全部；用户列表的 `deptId` 树过滤（#249）只是额外 AND，选中不可见部门自然零行、不放宽可见范围；日志的删除/清空/解锁是 gate-only，不套范围；解析器不缓存、不进 `/info`。
- 后台页面路径一律绝对：`/system/processSet/...`、`/system/processMgr/...`（#221）、`/system/sysUser`、`/system/sysRole`、`/system/sysMenu`、`/system/assignAuth`（V111，#222）、`/system/log/operLog`（V113，#214）与 `/system/log/loginLog`（V115，#216；两者共用目录 `log`）、`/system/notice`（V116，#218）、`/monitor/online`（V117，#235）、`/monitor/server` 与 `/monitor/data`（V118，#236）、`/monitor/cache` 与 `/monitor/cacheList`（V119，#237）、`/monitor/job`（V121，#238；六者共用目录 `/monitor`）、`/tool/api-doc`（V122，#246；系统工具唯一页面，目录 `/tool`）、`/system/sysDept`（V123，#247）、`/system/sysPost`（V124，#248）、`/system/config`（V127，#252）、`/system/dict`（V130，#251）；`/profile` 与 `/register` 不进后台菜单（登录即有 / 匿名）。`/info` 返回 `{name, avatar, roles[], permissions[], menus[], sessionId}`，`avatar` 是本人头像的已认证同源读端点 `/admin/system/profile/avatar/{userId}` 或空串（#254），`menus` 只含 type 0/1（`path`/`parentPath`/`title`/`type`/`hidden`/`sort`/`icon`），按钮点只进 `permissions`（ADR 0058；`sessionId` 为 ADR 0060 扩展）。
- 表结构迁移只加不改：`lautung-oa-server/src/main/resources/db/migration/V*.sql`，Flyway 按版本执行。需要元数据幂等的迁移写成 `db.migration` 下的 Java 迁移（V110/V116），种子 DML 放 `db/seed/`。
- 公告（ADR 0055）：正文只在 `NoticeService` 写入时经 jsoup `Safelist` 消毒一次，读侧不二次消毒；列表接口永不返回正文；`img src` 只接受 `/admin/notices/images/{id}`。图片复用私有附件桶的 `notices/` 前缀（`spring.servlet.multipart.max-file-size=6MB` 只为 5MB 业务上限留余量，附件仍走预签名直传）。读面 `GET /admin/notices/*` 登录即有，不设页面授予、不套数据范围；管理写面每个动作各要按钮点，没有 `system:notice:query`。已读回执唯一键 `(notice_id,user_id)`，撤回/删除/编辑都不清回执。
- `sys_oper_log` 采集守卫对 `/admin/system/*` 与 `/admin/monitor/*` 的写方法生效：公告的新增/修改/删除/发布/撤回/上传图片、在线用户的强退、定时任务的修改与手动执行都挂 `@OperLog`。
- `POST /admin/process/startUp` 的 `idempotencyKey` 可空，唯一索引 `uk_oa_process_idempotency_key` 按用户唯一（ADR 0032）：重复送达返回同一条审批；冲突后的重读必须在 `ApprovalWriter.startUp` 的事务之外（可重复读下事务内看不到对手已提交的行）。
