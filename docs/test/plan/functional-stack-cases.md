# 功能测试：真实栈套件用例（P0 / P1）

来源：[确定功能测试的范围与用例设计口径 #121](https://github.com/lautung/guigu-oa/issues/121) 的 resolution。
套件：`client/guigu-oa-client/tests/e2e-stack/`，命令 `npm run test:e2e:stack`（1 worker 串行、重试 0、
不装 `page.route`，真实浏览器 + 真实 `service-oa` + 真实 MySQL/Redis/MinIO，环境地址 `DEMO_ORIGIN`）。
数据策略：每轮运行生成 runId 写进请假原因与文件名，全部经真实 API/UI 造数，自清理可清理项。

定位是**回归基线**（承接 #108）：只覆盖「只有真实栈能证明」的缺口；单测、mock e2e、MockMvc
已确定性覆盖的状态机与契约不在此重复。

## P0（真实栈自动化，8 条）——功能回归基线的判定范围

| 用例 | 场景 | 覆盖的领域语义 | 主要断言 |
|---|---|---|---|
| P0-1 | 登录成功 / 失败（不区分用户不存在与密码错）/ 停用不能登录 / 退出 / 直达 URL 被拦 | GLOSSARY「登录」「停用」「退出」 | 落到待处理；失败 toast「认证失败」且不区分原因；停用「账号已停用」；退出与直达 URL 回登录页 |
| P0-2 | admin 与 user 的侧栏分组差异；user 直达配置 URL 落到待处理；admin 可进配置页 | GLOSSARY「配置权限」「菜单」「占用」 | 侧栏分组数；直达 `/system/sysUser` 的落点 |
| P0-3 | alice 按已发布模板发起含附件的请假审批，已发起列表可见 | GLOSSARY「发起审批」「附件」，ADR 0002 | 发起页可打开；附件经真实 MinIO 上传；oracle 在已发起列表与附件登记里核对 |
| P0-4 | bob 待处理 → 通过 → 已处理可见、alice 已发起状态更新 | GLOSSARY「待处理」「处理审批」「已处理」 | bob 已处理 status=2；alice 已发起 status=2；处理的是同一条 |
| P0-5 | bob 拒绝路径 | 同上（拒绝分支） | 双视角 status=-1（审批拒绝） |
| P0-6 | carol 抄送我的：完整表单/流转记录可见、附件可下载、只读 | GLOSSARY「抄送」「审批成员资格」，ADR 0011 | 详情无通过/拒绝/补传入口；下载内容与上传一致；oracle `isApprove=false`、`canUpload=false` |
| P0-7 | 手机 390 视口完成 登录 → 待处理 → 详情 → 通过 | GLOSSARY「统一客户端」（办事必须能在手机浏览器完成） | 全链路通过 + 无横向溢出 |
| P0-8 | 发起结果不明 → 核实 → 明确重新发起 → 两条审批都真实存在 | GLOSSARY「发起结果待确认」「重新发起」，ADR 0008 | `docker compose pause service-oa` 冻结制造真实网络级「结果不明」（axios 超时），解冻后原提交落库，重新发起后两条都在 |

**通过标准**（#121 §7）：P0 全部通过且无未关闭的 S1/S2 缺陷 = 功能回归基线通过。

## P1（真实栈自动化冒烟，5 组各 1 条 happy path）——失败记缺陷但不阻塞基线

| 用例 | 场景 | 覆盖的领域语义 |
|---|---|---|
| P1-1 | 模板发布 / 编辑：未发布可改可删，发布后冻结（含向导真实上传流程 zip） | GLOSSARY「未发布」「已发布」，ADR 0003/0005；每轮留下一个 runId 已发布模板（唯一不清理的残留） |
| P1-2 | 分配角色后菜单权限生效，撤销后消失 | GLOSSARY「配置权限」「分配角色」，ADR 0006/0015；doAssign 的 201 缓存失效语义用轮询消化 |
| P1-3 | 用户 / 角色 / 菜单 / 审批类型 CRUD 各一条 | GLOSSARY「配置」；菜单只能建在配置根下（服务端只允许维护配置菜单），建停用子节点 |
| P1-4 | 真实多页数据翻页（含末页与越界页） | 现场造 25 条；页数按真实总数动态计算 |
| P1-5 | 附件生命周期：发起前可删、发起后不可删、审批结束保留 | GLOSSARY「附件」，ADR 0002/0011；「发起前可删」走发起页 UI，暂被缺陷 #131 阻塞（test.fixme） |

## 明确不做（交给已有层或其他票，#121 §1）

- 5 个「待确认」中间态、迟到结果不覆盖、强制离开/占用细节 → 41 个 mock e2e 场景 + 单测已确定性覆盖；
- JWT 吊销、密码哈希、限流、XSS、上传内容安全 → 安全票（#113/#116）；
- 并发、容量、10k 数据 → 性能票（#112/#124）；
- WebKit / 1440 / 真机 → 兼容性票（#114/#117）；
- 23 个无 HTTP 断言的端点、错误码/分页/幂等矩阵 → 接口票（#120/#123）；
- Flowable 引擎内部、Flyway、H2 合同 → 服务端现有测试。

## 证据与记录约定（#122）

- 每轮产出 Playwright JSON/JUnit 报告（`tests/e2e-stack/test-results/e2e-stack/`），小摘要与报告副本入
  `docs/test/execution/` 与 `docs/test/evidence/`；失败用例保留 trace（不入仓，超限走本机）。
- 缺陷一 issue，`severity:S1`–`S4` 标签，修复后 `defect:fixed`，closed = verified。
