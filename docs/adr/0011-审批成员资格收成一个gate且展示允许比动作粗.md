# 审批成员资格收成一个 gate，展示允许比动作粗

`show` 的 `isApprove`、`approve` 的任务校验、附件的读/补传此前是三份实现：`show` 看实例内任一当前 assignee，`approve` 看 taskId + processInstanceId + assignee，附件在 `process.attachment` 里另有一套 `canRead/canUpload`。同一次审批的同一用户可能得到不同结论，且附件包反向拥有审批规则。现在把「某用户与某次审批的关系」收成 `process.membership.ApprovalMembership`：申请人、当前处理人、历史处理人、抄送人；`canRead`、`canUpload`、`canAct(taskId)` 从同一份证据派生；`show`、`approve`、附件、抄送都只消费它，`ProcessMembershipExtension` 也随 gate 搬进 `process.membership`，attachment 只依赖 membership。

`isApprove` 保持实例级「任一当前任务分配给我」，`canAct` 是任务级；在支持的顺序单任务模型里二者等价，并行/多实例任务暂不支持，真支持时再把展示改成 task-scoped。附件补传保持「申请人或当前处理人」，历史处理人和抄送人只读；审批结束后申请人仍可补传是现有行为，状态语义另议。详情/审批拒绝仍 403，附件拒绝仍 205；配置里的审批实例查询不是成员资格，由 `show` 在外层组合配置权限（候选 7）。代价是 `resolve` 一次读当前任务、历史与抄送：`approve` 与补传会读到它们不消费的证据，换来每次请求只有一份快照。
