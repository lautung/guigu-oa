# 配置写请求收成DTO且校验先于授权

配置类的写端点（`sysUser`、`sysRole`、`sysMenu`、`processType`、`processTemplate` 的 save/update，加上两个 doAssign）一直把实体和 Vo 直接当请求体：必填为空会一路写进库——`sysUser` 缺密码建出不能登录的账号，`doAssign` 缺 `userId`/`roleId` 会写出 null 关联行，`oa_process_type` 能建出没有名字的类型。ADR 0033 把这批实体排除在外，理由是顺序问题：`@Valid` 在 MVC 参数解析期执行，早于方法调用上的 `@PreAuthorize`，直接加约束会把「未授权 + 畸形体」从 `code=205` 变成 `201`，而 `FlywayMigrationContractTest` 正用 `{}` 钉着 205（#152）。

决定：配置写请求体收成请求 DTO，`@Valid` 放在参数上，**接受校验先于配置 gate**。拒绝顺序变成「认证（过滤器，401+208）→ 参数解析与校验（201）→ 配置 gate（205）→ 控制器方法」。

请求 DTO 的形状：

- 5 个实体各拆 save/update 两个 DTO（共 10 个），放在 `model` 的 `vo/system` 与 `vo/process`，命名 `XxxRequest`，各自带 `toEntity()`。
- **save 只创建**：DTO 不含 `id`，创建不由调用方选主键。
- **update 只要求 `id`**：其余字段为空即不覆盖，沿用 MyBatis-Plus 的空值策略；密码为空表示不改密。
- 创建侧必填按产品语义给：用户要 `username`/`password`/`name`，角色要 `roleName`/`roleCode`，菜单要 `parentId`/`name`/`type`/`path`，审批类型要 `name`，审批模板要 `name`/`processTypeId`。角色的 `description`、用户的 `phone`、菜单的 `component`/`icon` 保持选填——客户端要么不发、要么发空串，必填会让正常保存变 201。审批模板的流程 zip 不在必填内：草稿可以先没有，发布时才校验。
- `AssginRoleVo.userId`、`AssginMenuVo.roleId` 必填；两个列表选填，为空即清空授予。
- `SysUserController.save` 删掉「只有非空才编码」的分支：空白密码已在边界被 201 拒绝，提交的明文一律编码后落库。

## 考虑过的替代方案

- **把配置 gate 前移到 `HandlerInterceptor`**：顺序能保住 205，但要新增一套路径映射，gate 每次请求跑两遍（`ConfigurationGrant.snapshot` 每次读菜单树），与 ADR 0013「配置路由统一由 `@PreAuthorize` 上的 gate 判定」不一致。
- **在控制器方法体里 gate 之后显式调 `Validator`**：顺序也能保住，但 13 个端点各多一行，忘写就静默不校验——比顺序更差的失败模式；而且校验出现两套约定（未 gate 的路由用注解，gate 过的用手工调用）。
- **给 MyBatis 实体直接加注解**：`SysUser.password` 在 save 必填、update 必须可空，一套注解表达不了；`update` 要 `id` 而 `save` 不要。要靠校验分组才行，而校验分组在本仓库零先例，漏写 `groups` 会静默落回 Default 组。
- **只给不涉及 `@PreAuthorize` 的实体补约束**：等于承认配置类接口没有边界约束，issue 的一半没做。

## 后果

- 顺序契约变化：已认证但未被授予的用户提交畸形体，从 205 变成 201 + 字段文案。匿名请求仍是 401+208——`AuthorizationFilter` 在 MVC 之前。`FlywayMigrationContractTest` 里钉 205 的用例改用良构体（那才是 gate 的证据），另加一条 `{}` → 201 钉新顺序；`RequestValidationContractTest` 与接口套件 `b-menu.spec.ts` B22 各有一条同义用例。
- 菜单保护的负例原本在测别的东西：`{path:"/work"}` 的根改名先被配置 gate 以「只能维护配置菜单」拒绝，永远到不了「菜单路由不可重定义」。这批断言现在同时钉文案，并补了一条换到另一个配置根（`/processSet`）的用例真正走到保护路径分支。
- `POST /admin/process/processTemplate/save` 带 `id` 不再更新已有模板：`saveUnpublished` 按 `id` 分支，而 save 的 DTO 已不含 `id`，故 save 只创建。客户端与接口套件都走 update，不受影响。
- 空白密码不再能落库：`SysUserControllerTest` 的「空白密码不编码」用例改为「提交的密码一律编码」，空口令由合同测试以 201 断言。
- `doAssign` 缺 `userId`/`roleId` 不再写出 null 关联行。
- 未做：varchar 长度与枚举/格式约束、`RefreshTokenVo` 的必填、`batchRemove` 空列表语义、客户端配置表单的本地必填规则。
- 回归锚点：`RequestValidationContractTest`（逐端点的字段文案 + 两条顺序用例）、`FlywayMigrationContractTest`（gate 判定改由良构体触发）、`SysUserControllerTest`、`SysRoleControllerTest`、`SysMenuControllerTest`、`ProcessAdminControllersTest`、接口套件 `tests/api/b-menu.spec.ts`。
