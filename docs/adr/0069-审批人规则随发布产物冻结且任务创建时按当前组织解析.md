# 审批人规则随发布产物冻结，任务创建时按当前组织解析

ADR 0065 把审批人来源扩成 BPMN 写死用户名、部门负责人、角色、岗位，并要求解析规则随发布冻结。研究 #269 的约束是：Flowable 的 assignee 表达式与 TaskListener 在任务创建时求值；`candidateGroups` 的成员要靠 Flowable IDM 解析，本仓没有 IDM；本仓发布是上传 zip 原样部署，模板表没有审批人字段，客户端只上传 zip、没有 BPMN 设计器；发布证据只哈希 zip。所以「规则放哪、谁在什么时候解析、解析不到人怎么办」必须先定，否则动态审批人没有可落地的形状。本 ADR 定这套形状。

决定：

- **来源与优先级**：每个节点单选一种来源——BPMN 写死用户名、部门负责人、某角色、某岗位。**节点规则优先于 BPMN assignee**（配置了规则就覆盖，没配规则的节点沿用 BPMN assignee），模板设置页明示「此处规则将覆盖流程 zip 中的 assignee」。发布校验要求每节点至少有一个来源（规则或 BPMN assignee），两者都缺拒绝发布。
- **规则的存储**：模板子表按 `template_id + BPMN userTask id + 来源类型 + 目标 id` 存规则，未发布可改。上传模板时服务端解析 zip 里的 BPMN userTask 列表供配置页使用；解析不出 BPMN 的 zip 可以保存，但发布时拒绝。
- **发布合成产物**：发布时把规则生成为 `oa-approvers.json`，与上传 zip 合成一个**发布产物**（content-addressed），发布证据的路径与 sha256 指向合成件；合成件部署到引擎。已发布规则随产物冻结，不可再改；上传原件保留，但不再是发布产物。
- **解析**：全局 `TASK_CREATED` 监听器按**部署里冻结的 sidecar**解析，不读「当前模板」。来源语义：
  - BPMN 写死用户名：沿用原行为。
  - 部门负责人：发起人所在部门的**直接负责人**（`sys_dept.leader_user_id`，只认启用用户），不逐级向上找。
  - 角色/岗位：取启用成员集合；**剔除申请人**（角色/岗位可多人，自审回避）；剔除后为空 → 解析失败。
  - 部门负责人就是申请人时**保留自审**（组织里没有上级数据，硬失败会让负责人无法提交任何申请）；转办与加签的目标不能选本人或申请人。
- **多人来源的语义**：解析成一人 → 直接指派；解析成多人 → 任务以**候选用户**下发，任一候选人处理即**认领**（处理动作本身认领），其余人不再需要处理；并发下后到者按「已被其他人处理」拒绝。打开详情不认领。
- **解析时机**：**任务创建时按当前组织解析**，不预快照。首节点解析不到 → 发起失败；中途节点解析不到 → 该次处理失败并指明节点，修好组织后重试。绝不静默生成无人任务、不跳过、不自动转管理员。
- **冻结的边界**：冻结的是**规则**，不是人——同一份已发布模板在不同时间解析出不同部门负责人/角色成员是预期行为；解析器代码属于产品代码，不随模板冻结，ADR 0003 的「内容固定」只覆盖发布产物与规则。
- **组织数据迁移**：`sys_dept` 新增 `leader_user_id`，按 `leader` 姓名唯一匹配启用用户回填；重名或无匹配置空并记日志；随后删除 `leader` 列；部门表单改用户选择器；负责人停用或删除视为无负责人。迁移不阻断启动。
- **旧模板**：没有 sidecar 的已发布模板，监听器 no-op，BPMN assignee 照旧生效。

考虑过的替代方案：

- **BPMN 里手写表达式（无 UI）**：3–30 人的管理员没有 BPMN 编辑能力，产品等于不提供动态审批人。
- **发布时改写 BPMN 注入表达式**：XML 手术会改用户的流程结构，BPMN 语法与命名空间风险高；sidecar 是纯增量。
- **运行期读模板配置**：发布证据失效，同一模板的实际规则可被事后改动，ADR 0065 已拒绝。
- **`candidateGroups` + Flowable IDM**：角色/岗位/部门在 `sys_*` 表里，再养一套组等于两套组织真相。
- **发起时快照全部节点审批人**：分支里不执行的节点也会被预校验（例如金额分支），一个没人可审的死分支会挡住整条发起；组织调整也不会作用于在途审批。
- **解析不到就转管理员/跳过节点**：静默改路由比失败更难排查；小团队里显式失败能立刻暴露组织数据缺口。指定人员与转管理员属于第二波。
- **只允许唯一人来源（部门负责人）**：地图明确要求角色/岗位进第一波。
- **角色/岗位按会签（全部通过）**：会签是第二波的节点级配置；第一波固定候选认领（或签）语义。

后果：

- ADR 0003/0046 修订：发布产物从「上传原件」变为「上传 zip + 规则 sidecar 的合成件」；证据 sha256 覆盖合成件；已发布冻结语义不变。
- 模板设置页新增节点审批人配置与「规则覆盖 assignee」提示；上传接口增加 BPMN 节点解析。
- 组织页部门负责人从姓名文本改用户选择器；迁移回填日志。
- 发布校验新增：节点来源缺失、规则目标不存在/停用 → 201 命名拒绝。
- 发起/处理新增失败文案：第 N 步审批人无法解析（部门负责人/角色/岗位）。
- 合同测试新增：发布合成与证据、规则覆盖、部门负责人、角色多人候选认领、自审回避、解析失败、旧模板 no-op、负责人迁移。
- 未做：审批人为空时的指定人员/转管理员兜底、连续多级部门负责人、发起人上级、表单内审批人、委托。
