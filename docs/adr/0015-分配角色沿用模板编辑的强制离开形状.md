# 分配角色沿用模板编辑的强制离开形状，强制导航收进 module

ADR 0010 把模板编辑的“这一次打开是否还能继续”收进编辑 module，并明确把分配角色同类的 `requestLeave(force)` 留到之后再评估。现在把分配角色补齐成同一形状：`createAssignRoles` 的 adapter 增加 `occupancy()`（只回答 `allow | redirect` 与目标地址）与 `replace()`，lease 的 `requestLeave()` 去掉 `force`，新增 `environmentChanged()`；占用判定、强制离开、确认框关闭与强制导航都由 module 决定，`sysUser/index.vue` 只保留 resize、focus、token 与菜单 watch 的事件接线，并删掉 `mustLeave` 与 `enforceEntry`。占用仍是 surface 的规则，module 只消费 `allow | redirect`，不读 viewport、菜单或路由；取数与 `resolveClientSurface` 留在浏览器 facade，避免应用级 module 持有页面级闭包。

与模板编辑不同的是分配角色 module 是应用级、按认出缓存，弹窗只租用 lease。因此 `environmentChanged()` 挂在 lease 而不是 module 上；lease 增加 `released` 状态，强制释放后弹窗据此关闭自己，而不是从 phase 推断——`saving` / `unconfirmed` 被强制离开时必须保留原 phase 与本地记录，置为 `closed` 会破坏“分配结果待确认”的恢复语义。身份被替换时不经确认、释放 lease、按 `getDefaultPostLoginRoute()` 用 `replace` 导航；身份被清空时只释放不导航，把登录跳转留给认出流程。强制离开对各 phase 的丢弃规则保持现状：`loading` / `read-error` / `ready` 丢弃本次打开，`saving` / `unconfirmed` 只释放 lease 并保留提交记录，迟到成功在身份未变时仍刷新资料与菜单但不提示、不抢导航。清理入口沿用 ADR 0010 的 `dispose()` 命名。

确认框的关闭也收回 module：只有 module 正在等待 `confirm` 时，`environmentChanged()` 才调用 `dismissConfirm()`；页面不再无条件 `ElMessageBox.close()`，避免缩放或失焦误关其他确认框。这条修正随本次搬移一起落地，不单独立项。

否决的替代方案：在页面保留 `mustLeave`、只把判断挪位置，候选指出的泄漏不变；靠全局 `ClientSurfaceHost` 跳转让路由守卫处理强制离开，会让强制跳转走普通离开确认（弹未保存确认），身份清空时也永远不会关弹窗；把 `resolveClientSurface` 放进 module 会破坏 surface 与编辑生命周期的分工。ADR 0006 的“分配结果待确认”语义不变，本次只把强制离开的 enforcement 从页面搬回 module。

合同测试在 `assign-roles` 的 module interface 上新增占用 redirect、强制离开抢在进行中的确认、身份替换与清空、环境未变不打断、保存中强制离开五类；现有端到端用例的“缩成手机”继续证明页面接线，不新增浏览器用例。

Related: ADR 0010（形状来源）；ADR 0006（分配角色语义）；ADR 0013/0014（占用与配置授予）。
