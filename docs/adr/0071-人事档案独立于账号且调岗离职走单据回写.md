# 人事档案独立于账号，组织归属由档案写回，调岗离职走单据回写

蓝图 2.0 把人事档案定为 W2 的独立主数据，但只钉了「账号与员工分离」与三页轮廓；员工能否无账号、字段集、历史记录、离职后的账号处置与权限面留给 #273。本仓现状：`sys_user` 没有任何工号/合同/离职字段，`sys_dept.leader` 仍是姓名文本，没有 `hr_*` 表；用户管理页可直接改部门/岗位，数据范围五档已能套新列表。本 ADR 定形状与表结构草案，不写实现。

## 决定

### 员工与账号

- `hr_employee.user_id` 可空、非空时唯一：一个员工最多关联一个账号，一个账号最多对应一个员工；允许无账号档案（待入职、已离职保留档案）。
- 一人一档：身份证填写时唯一，`employee_no` 系统生成（`EMP0001` 递增）且不可手改。离职后再入职复用同一档案、工号不变，写一条新的「入职」异动；再入职是显式动作（`hr:employee:rehire`），**不自动启用账号**——旧凭证已随离职作废，启用由用户管理页的状态开关显式完成。
- 档案只**关联**已有账号，不负责创建账号；建号仍在用户管理页（用户名/密码/角色）。
- 姓名/手机在**新建档案并绑定账号**时一次性镜像到账号（档案为空则从账号回填）；之后各自维护，不强制相等。它们不影响权限、审批人解析或数据范围，与部门/岗位不同。

### 组织归属的唯一写入口

- `hr_employee.dept_id` + `post_id` 是「有档案员工」的任职真相；档案保存、调岗回写在同一事务里把 `sys_user.dept_id` 与 `sys_user_post` 覆盖为档案的值。
- 岗位在档案上是**单值主岗位**；写账号时整体替换 `sys_user_post` 为这一条。现有 `sys_user_post` 的多值能力保留给无档案账号，不新增档案侧关系表。
- 用户管理页对「已有档案的用户」继续可改姓名/手机/状态/角色，但**部门与岗位只读**，服务端拒绝写入；无档案账号维持现状。
- 跨模块经端口：auth 侧定义「该用户是否有档案」的只读端口（hr 实现，缺席按无档案），用户删除保护与用户页组织字段只读都走它；hr 侧调用 auth 的用户写服务完成镜像。auth 不反向依赖 hr。部门/岗位的删除保护同样把档案引用算进去。

### 档案字段与状态

- 主档必填：姓名、手机、入职日期、部门、主岗位、工号（系统生成）。
- 选填但填了校验：身份证（18 位格式 + 唯一）、生日、性别（0 未知 / 1 男 / 2 女，固定枚举，不走字典）、紧急联系人姓名+电话（成对填）、直属上级（自关联 `hr_employee`，**不参与审批人解析**；审批人来源仍是 ADR 0065/0069 的部门负责人/角色/岗位）、备注。
- 不自动从身份证解析生日/性别。
- 状态只有「在职/离职」；入职日期在未来的档案显示派生的「待入职」，到日期不自动改状态，不引定时任务。
- 档案删除仅限录入错误：无账号、无合同、无单据、除系统写入的「入职」外无异动；有历史只能离职。删除前把身份证置空以释放唯一索引（与用户删名的既存做法一致），工号不回收。

### 劳动合同

- 独立 `hr_employee_contract`，一合同一行；续签 = 新行 + 旧行置「已续签」；提前结束置「已终止」；到期由 `end_date` 推导，不落状态。无固定期限合同的 `end_date` 为空。
- 到期角标固定 30 天：员工档案列表行角标 + 人事统计卡「30 天内到期 / 已到期」；合同页可筛选；不新开通知出口（蓝图）。
- 合同续签/终止是 HR 记录动作，**不走审批**；首版不做合同附件扫描件。

### 异动

- 一张 `hr_employee_change`：类型（入职/调岗/离职/其他）、变更前后部门与岗位、生效后的部门快照、生效日期、来源单据（`business_type`/`business_id`）、操作人、原因。
- 主档只存当前值，历史全在异动行；建档写入职，调岗单通过写调岗，离职单通过写离职；合同续签只写合同行，不写异动。
- 异动页只读（无按钮点），数据范围按生效后部门快照 + 员工账号快照；合同页按员工当前部门 + 账号快照套同一档；记录本身不更新、不删除。

### 调岗单与离职单

- 两张业务单据表 `hr_transfer`/`hr_resign`，生命周期同 ADR 0067：先落草稿 → 提交即发起（状态 CAS 到审批中）→ 通过/拒绝/撤回；拒绝/撤回可改后重新提交（同一单据、单据号不变；单号即单据 id，不另设业务编号）。
- 调岗单字段：员工、新部门、新岗位（单值）、生效日期、原因。通过后同事务更新档案部门/岗位（组织归属由档案写回，见上）+ 写一条调岗异动。
- 离职单字段：员工、离职日期、离职原因（字典 `hr_resign_reason`）、交接说明（自由文本，不做交接人引用）。通过后同事务：档案置离职并记离职日期、写离职异动、关联账号停用（`status=0`）并推进 `token_version`（旧凭证永久作废，避免再入职启用后复活）；不删在线会话、不强退——按 GLOSSARY「停用」：监控仍能看到会话，下次核验失败。
- 离职日期在未来也立即停用：离职单应在最后工作日后提交/通过，不引按日期停用的定时任务。
- 审批模板经 `oa_business_template` 映射到已发布模板；未绑定/未发布/发布证据失效 → 发起 201 拒绝、单据留草稿。
- 单据的草稿/被拒/被撤回在员工档案详情的「人事单据」区展示并可重新提交；审批中/通过的单据另在审批详情与异动记录体现。不新增单据列表页，蓝图三页不变。

### 页面、按钮点与数据范围

- 三页：`/business/hr/employee`、`/business/hr/change`、`/business/hr/contract`；一级目录 `/business`、二级 `/business/hr`；权限前缀 `hr:`。
- 按钮点：`hr:employee:add|edit|remove|transfer|resign|rehire`、`hr:contract:add|renew|terminate`；读端点只判页面授予；异动页无按钮点。
- 员工档案与合同按 `hr_employee.dept_id`/`user_id` 套数据范围；异动按生效后部门快照/`hr_employee_change.user_id`；详情读与单据读同样套，不能靠 ID 绕过列表范围。

### 首版不做

合同附件、转正/试用期、直属上级进审批链、合同续签走审批、员工档案导入/导出、离职交接人引用、人事办事面（我的合同/我的异动）、按日期定时停用账号。

## 表结构草案（不执行）

沿用仓库约定：无外键；公共字段 `create_time`/`update_time`/`is_deleted`；索引单独 `CREATE INDEX`（MySQL/H2 双兼容）。

```sql
CREATE TABLE hr_employee (
  id BIGINT NOT NULL AUTO_INCREMENT,
  employee_no VARCHAR(20) NOT NULL,
  user_id BIGINT DEFAULT NULL,
  name VARCHAR(20) NOT NULL,
  phone VARCHAR(20) NOT NULL,
  gender TINYINT NOT NULL DEFAULT 0,          -- 0 未知 / 1 男 / 2 女
  birthday DATE DEFAULT NULL,
  id_card VARCHAR(18) DEFAULT NULL,
  emergency_contact_name VARCHAR(20) DEFAULT NULL,
  emergency_contact_phone VARCHAR(20) DEFAULT NULL,
  dept_id BIGINT NOT NULL,
  post_id BIGINT NOT NULL,                    -- 单值主岗位
  leader_id BIGINT DEFAULT NULL,              -- 自关联 hr_employee.id，仅展示
  hire_date DATE NOT NULL,
  leave_date DATE DEFAULT NULL,               -- 最近一次离职日期；在职时为空
  status TINYINT NOT NULL DEFAULT 1,          -- 1 在职 / 0 离职
  remark VARCHAR(255) DEFAULT NULL,
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE UNIQUE INDEX uk_hr_employee_no ON hr_employee (employee_no);
CREATE UNIQUE INDEX uk_hr_employee_user ON hr_employee (user_id);
CREATE UNIQUE INDEX uk_hr_employee_id_card ON hr_employee (id_card);
CREATE INDEX idx_hr_employee_dept_status ON hr_employee (dept_id, status);
CREATE INDEX idx_hr_employee_leader ON hr_employee (leader_id);

CREATE TABLE hr_employee_contract (
  id BIGINT NOT NULL AUTO_INCREMENT,
  employee_id BIGINT NOT NULL,
  contract_type TINYINT NOT NULL,             -- 1 固定期限 / 2 无固定期限 / 3 实习 / 4 劳务
  start_date DATE NOT NULL,
  end_date DATE DEFAULT NULL,                 -- 无固定期限为空
  signed_date DATE DEFAULT NULL,
  status TINYINT NOT NULL DEFAULT 1,          -- 1 生效 / 2 已续签 / 3 已终止；到期由 end_date 推导
  remark VARCHAR(255) DEFAULT NULL,
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE INDEX idx_hr_contract_employee_status ON hr_employee_contract (employee_id, status);
CREATE INDEX idx_hr_contract_end_status ON hr_employee_contract (end_date, status);

CREATE TABLE hr_employee_change (
  id BIGINT NOT NULL AUTO_INCREMENT,
  employee_id BIGINT NOT NULL,
  user_id BIGINT DEFAULT NULL,                -- 员工关联账号快照，数据范围「本人」列
  change_type TINYINT NOT NULL,               -- 1 入职 / 2 调岗 / 3 离职 / 9 其他
  old_dept_id BIGINT DEFAULT NULL,
  dept_id BIGINT NOT NULL,                    -- 生效后的部门快照，数据范围「部门」列
  old_post_id BIGINT DEFAULT NULL,
  post_id BIGINT NOT NULL,                    -- 生效后的岗位
  effective_date DATE NOT NULL,
  business_type VARCHAR(64) DEFAULT NULL,     -- hr.transfer / hr.resign；入职为空
  business_id BIGINT DEFAULT NULL,
  operator_user_id BIGINT NOT NULL,
  reason VARCHAR(255) DEFAULT NULL,
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE INDEX idx_hr_change_employee_date ON hr_employee_change (employee_id, effective_date);
CREATE INDEX idx_hr_change_dept_type ON hr_employee_change (dept_id, change_type);
CREATE INDEX idx_hr_change_user ON hr_employee_change (user_id);
CREATE INDEX idx_hr_change_business ON hr_employee_change (business_type, business_id);

CREATE TABLE hr_transfer (
  id BIGINT NOT NULL AUTO_INCREMENT,
  employee_id BIGINT NOT NULL,
  user_id BIGINT DEFAULT NULL,                -- 员工关联账号快照
  dept_id BIGINT NOT NULL,                    -- 提交时员工部门快照，数据范围「部门」列
  new_dept_id BIGINT NOT NULL,
  new_post_id BIGINT NOT NULL,
  effective_date DATE NOT NULL,
  reason VARCHAR(255) DEFAULT NULL,
  status TINYINT NOT NULL DEFAULT 0,          -- 0 草稿 / 1 审批中 / 2 通过 / -1 拒绝 / -2 撤回
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE INDEX idx_hr_transfer_employee_status ON hr_transfer (employee_id, status);
CREATE INDEX idx_hr_transfer_dept_status ON hr_transfer (dept_id, status);

CREATE TABLE hr_resign (
  id BIGINT NOT NULL AUTO_INCREMENT,
  employee_id BIGINT NOT NULL,
  user_id BIGINT DEFAULT NULL,                -- 员工关联账号快照
  dept_id BIGINT NOT NULL,                    -- 提交时员工部门快照，数据范围「部门」列
  leave_date DATE NOT NULL,
  reason_code VARCHAR(64) DEFAULT NULL,       -- 字典 hr_resign_reason
  handover_note VARCHAR(500) DEFAULT NULL,
  status TINYINT NOT NULL DEFAULT 0,          -- 同 hr_transfer
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE INDEX idx_hr_resign_employee_status ON hr_resign (employee_id, status);
CREATE INDEX idx_hr_resign_dept_status ON hr_resign (dept_id, status);
```

## 种子草案（不执行）

- `sys_menu`：目录 `/business`、目录 `/business/hr`、三页与上述按钮点；补授 `super_admin`，保持幂等。
- `oa_business_template`：`hr.transfer`、`hr.resign` 各映射到一份已发布审批模板；映射由迁移建，模板本身由部署/演示种子准备。
- 字典 `hr_resign_reason`：演示种子给常见项（个人原因/家庭原因/合同到期/其他），运行时可通过字典页维护。

## 考虑过的替代方案

- **账号必填 1:1**：待入职要开无用账号，离职要留账号，人事状态与登录状态绑死。
- **一次任职一档、再入职新建档案**：工号与历史断裂，同一个人留下两条主数据。
- **`sys_user` 作组织归属唯一真相、档案不存部门岗位**：无账号员工无法表达任职，也违反蓝图数据范围的部门列。
- **档案与账号各写部门、不强制相等**：调岗后数据范围与审批人解析仍按旧部门，漂移不可见。
- **合同字段放档案**：只有一份合同，续签丢历史。
- **每类异动一张表**：多养三张同形表，读侧还要合并。
- **离职只回写档案、账号手动停用**：漏停用就是安全洞。
- **按离职日期定时停用**：为小团队引一个跨日任务与「已离职仍可登录」的窗口。
- **删除用户时保留档案并断链**：账号删除变成不可逆的档案断链，历史不可读。
- **独立单据列表页**：蓝图三页已定，单据生命周期挂员工详情即可。

## 后果

- 用户管理页需要「有档案则部门/岗位只读」的服务端拒绝与客户端展示；用户删除需要档案存在性保护；部门/岗位删除保护要把档案引用算进去。三者都经 auth 侧端口，auth 不依赖 hr。
- 新增 `lautung-oa-hr` 模块：依赖 `auth`（用户读写）、`process`（`BusinessApprovalStarter`/`BusinessApprovalCallback`）、`security`（`DataScopeProvider`）、`model`、`framework`、`common`；auth/process 不反向依赖 hr。
- 蓝图 §4 数据范围表补合同与调岗/离职单；§5 原则 1 的「员工是否可无账号」由本 ADR 钉为可空。
- GLOSSARY 增补员工档案、任职、异动、劳动合同、待入职、再入职、调岗单、离职单。
- 实现票要给出 `oa_business_template` 的两条映射与演示审批模板；未绑定即发起失败的路径必须显式测。
- 迁移编号从下一可用版本起（当前 V133）；索引建完用实发计划验（#185 教训），H2 合同测试跑真迁移。
