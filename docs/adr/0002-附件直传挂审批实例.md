# 附件直传挂在审批实例上，权威在元数据表

业务附件挂在一次审批（`oa_process`）上，发起人与审批人补传是同一种东西；独立于表单，**不以** `form_values` 里的 URL 为权威。采用预签名直传到私有对象存储并登记元数据：本地 compose 用 MinIO，线上用 R2。发起后不可删，结束后保留；pending 孤儿用 TTL 回收。流程 zip 是部署产物，只进可配置外部目录，不进附件桶与附件表。

备选「挂在流转记录上」或「只塞进 form-create 上传字段」会拆开同一次请求的文件面，或与直传鉴权/删除语义打架，故弃。

**2026-11-09 修订（#275）**：附件也可挂业务单据——`oa_attachment` 增加 `business_type`/`business_id`（镜像 `oa_process` 的业务键），元数据表仍是权威；业务归属附件不进草稿 `PENDING` 的 TTL 清理，下载 gate 是业务单据读权限；提交审批时复制成 `process_id` 快照行（共享 `object_key`），审批成员仍按 ADR 0011 下载；对象只在没有任何未删附件行引用时物理删。见 ADR 0072。
