# 审批表单值只按文本呈现，不再注入 HTML

#142 复现出一个 S1：发起人把 `<img src=x onerror="window.__secXss=1">` 填进「请假原因」，
处理人打开待处理列表时 `WorkListPage.vue` 用 `v-html` 渲染 `summaryFields`，点进详情时
`pending/detail.vue` 又用 `v-html` 渲染 `formFields`，两处都执行了脚本。统一客户端把
access/refresh token 放在非 HttpOnly Cookie（`src/utils/auth.ts`），脚本可以直接读走并外传，
等同于账号接管。安全基线记为 SEC-XSS-01。

现在审批表单值只作为文本呈现。新增唯一入口 `src/work/form-values.ts`：
`formFieldText` 把 `formShowData` 里存下来的任何值转成一段显示文本（字符串原样保留，
`null`/`undefined` 变空串，数组按顿号连接并丢掉空项，其它对象用 JSON 表示），
`formFields` 按存储顺序把整张表单映成字段列表。列表的 `summaryFields` 只在 `formFields`
之上过滤隐藏键，详情页直接调用 `formFields`；`WorkSummaryField.value` 的类型从 `unknown`
收到 `string`，两个页面都只做 `{{ field.value }}` 插值。Vue 的文本插值在编译期就走转义，
不存在“忘了转义”的分支；`v-html` 在客户端源码里归零。

拆掉了配套的图片假设：列表的 `::v-deep img` 与详情的 `:deep(img)` 只服务于“字段值是
`<img>` 标签”这一旧前提，值不再注入 HTML 后没有对象可作用，一并删除。历史上 `图片`
字段在列表里继续隐藏（`LIST_HIDDEN_FIELD_KEYS` 不动）；如果以后要显示图片，应当从 URL
字段用 `<img :src>` 渲染，并受 #139 定下的 `img-src` 白名单约束，而不是把存储的 HTML 放回页面。

否决的替代方案：引入 DOMPurify 白名单清洗——产品没有任何字段需要 HTML 语义，
form-create 的上传组件存的是 URL 字符串（`@form-create/component-elm-upload` 的 `toValue`），
清洗器只为一个不存在的需求留下依赖、白名单与绕过面，而且清洗器自身的历史漏洞会变成新的
XSS 入口；只对 `图片` 字段保留 `v-html`、其余走文本——把同一个执行面按字段名留一个例外，
字段名来自模板作者，等于把开关交给了攻击面；在服务端剥离标签——输入侧清洗会改变
`formData` 与 `formShowData` 的可信内容，且未来任何新的展示端（导出、通知）仍要重新回答
同一条转义问题，输出侧文本化才是唯一不变式。

CSP（ADR 0026 的 `script-src 'self'`）继续作为兜底，但修复不依赖它：Vite dev server 不发
CSP，内联 `onerror` 在开发态本来就能执行；构建产物里它只是第二层。代价：存量数据里若真有
按 HTML 存下的表单值，现在会按字符显示（这正是“只作为文本显示”的预期结果）；多行文本靠
详情页新增的 `white-space: pre-wrap` 保留换行，数组值显示为「甲、乙」而不是逗号拼接。

守卫分四层：ESLint 把 `vue/no-v-html` 从推荐配置的 `warn` 提成 `error`，`npm run verify`
（以及 CI 的客户端检查）从此拒绝任何重新引入的 `v-html`；`form-values` 的模块用例钉住规整
规则；列表页与详情页的挂载用例断言值里带 `<img onerror>` 时 DOM 不出现 `img` 元素、页面
文本保留原始字符串（去掉 `v-html` 前后分别红绿）；SEC-XSS-01 在真实栈上除了断言
`window.__secXss` 为空，还断言列表与详情可见文本包含原样载荷，避免将来用其它注入方式
“换一种写法”重新通过。
