# 考勤组绑固定班、事件流水读时推导日状态，假期余额走账本且审批通过才扣减

蓝图 2.0 把考勤定为 W3：考勤组 + 固定班、网页打卡、后台补卡、假期类型/发放/流水、请假单（扣余额）、加班单（调休余额）、月度统计，出口判据是「打卡 → 请假审批 → 余额扣减 → 月统计」闭环；首版边界钉死不做外出/出差、排班、弹性工时、多地点，补卡由后台直接改记录不走审批。§9 把域内字段、打卡判定、余额规则与统计口径留给本票。本仓事实：服务端无任何考勤存量代码，main 迁移最高 V120；ADR 0066/0067 已定业务单据两态、业务键、提交即发起与同事务回写；ADR 0071/0072 已定状态档 0/1/2/-1/-2、单号即 id 与展示走 join 不依赖 auth。本 ADR 定形状与表结构草案，不写实现。

## 决定

### 考勤组与班次

- 班次独立表：名称、上班时刻、下班时刻、可选午休起止、宽限分钟（默认 0）、备注。可建多个班次定义；时刻必须同一天内（下班晚于上班），**不支持跨天班**。午休只用于展示与算日工时，不参与迟到/早退判定。
- **日工时** = 下班 − 上班 − 午休（无午休不减），兜底 8 小时；用于余额单位换算与展示，不落库。
- 考勤组：名称、绑定**一个**班次、每周工作日多选（默认周一至周五）、成员**直接选人**（不按部门圈人——部门归属会漂移，数据范围仍按 `sys_user.dept_id` 另算）。
- 成员表一人最多一组（`user_id` 唯一）；成员移除是**硬删**（纯关系表，等同 `sys_user_post` 的整体替换，审计走操作日志）。
- 无组账号没有考勤义务：不能打卡，不进统计，不出现在打卡记录列表。
- 班次/考勤组/节假日/假期类型都是配置数据，不套数据范围（ADR 0052）。

### 节假日日历

- 全局节假日表：日期（唯一）、名称、类型（1 休假日 / 2 补班日）。HR 手动维护，不自动对接外部日历；对所有考勤组生效。不做则法定假落在工作日上全员缺卡，真跑判据不可接受。
- **工作日判定公式**：(星期 ∈ 组工作日 且 该日非休假日) 或 该日是补班日。
- 行删除为硬删（配置修正，操作日志留痕）；维护入口在「考勤组与班次」页的一个区块，蓝图五页菜单不变。

### 打卡

- 办事打卡页显示今日班次与两张卡状态，「上班打卡」「下班打卡」两个按钮；一律以**服务器时间**为准；允许重复打，上班卡取最早、下班卡取最晚。
- 非工作日提交打卡按 201 拒绝（「今日无排班」）；节假日表配错由 HR 修正后补卡兜底。
- 迟到 = 上班卡晚于上班时刻 + 宽限分钟；早退 = 下班卡早于下班时刻 − 宽限分钟；迟到/早退**次数按卡计**（存在该卡且超线即计一次，不因当日整体状态为缺卡而漏计）。
- 缺卡不引定时任务，**读时推导**：当日为工作日且已过下班时刻仍缺槽位才算缺卡（按天计，任一槽位缺失即缺卡天）；未到下班时刻只显示「未打卡」。

### 存储与日状态推导

- 只落**打卡事件流水表**（每次一行：用户、日期、槽位、时刻、来源、补卡操作人）。**不建每日考勤日报表、不建统计表、不引定时任务**——日报会在打卡/补卡/请假回写/冲正处引入多处同步写，读时推导在 30 人 × 31 天规模毫无压力（对齐「派生不落表」先例）。
- 槽位取值规则：有补卡行取**最新一条补卡行**，否则上班取最早网页行、下班取最晚网页行。补卡行 append-only，重复补卡追加新行、取最新，原网页行保留可查。
- 补卡 = 后台插入来源「补卡」的记录行（指定日期 + 上/下班时间，可只补一槽），写操作日志（蓝图已定不走审批）。
- 逐日状态优先级：请假(类型) > 缺卡 > 迟到且早退 > 迟到 > 早退 > 正常；非工作日显示休息日/休假日/补班日（当天有打卡也照常显示休息日）。

### 假期类型与余额账本

- 假期类型用**独立配置表**（字典装不下余额行为）：名称、是否需要余额、是否加班入账目标（仅调休开启，全局唯一，service 校验）、状态、排序。预置五项：年假（余额）、事假、病假、调休（余额 + 加班入账）、婚丧产假；运行时可维护；类型被流水与单据引用，**只停用不删除**。
- 余额走**流水账本**（一行一流水，签好 `change_hours`）：发放（HR 手动，支持一次选多人每人一行，可为负数调整行）、扣减（请假审批通过回调同事务写）、入账（加班单通过回调写调休）。发放与调整行**不改不删**，发错用负数行冲抵。余额 = Σ(change_hours)。
- **不做结转/过期自动规则**：年度额度由 HR 每年发放表达。
- **可用余额** = Σ发放 + Σ入账 − Σ已扣 − Σ**在途**（审批中的请假单按单上已定稿的小时数预计，不引冻结表——单据自身的审批中状态就是冻结）。
- 余额不足时**提交直接 201 拒绝**（只对需要余额的类型校验，事假/病假不限量）；通过回调**不再二次校验**——校验失败无法把「通过」动作顶回去，HR 中途调整发放造成的超扣让它显性可见（页面显示负余额）。

### 请假单与加班单

- 业务键 `attendance.leave` / `attendance.overtime`（ADR 0067 值域）；状态档 0 草稿 / 1 审批中 / 2 通过 / -1 拒绝 / -2 撤回；单号即单据 id；提交 = 状态 CAS + 校验 + `BusinessApprovalStarter`（客户端幂等键必填）同一事务；模板按 `oa_business_template` 解析，缺失/未发布/发布证据失效 → 201 拒绝、单据留草稿。
- 请假单：假期类型、开始日期、结束日期、天数、小时数、事由。**整天粒度**（不做 0.5 天/小时假）；天数与小时数由服务端提交时按当时班次定稿（提交时快照原则），休假日剔除、补班日照算；区间全为休假日（天数 0）201 拒绝；与本人已通过/在途请假**日期重叠 201 拒绝**。
- 加班单：日期、开始时刻、结束时刻、小时数、事由。时长服务端算，结束必须晚于开始、**同一天内，跨天拆两天提交**；允许休息日加班，不与打卡记录交叉校验；不做重叠校验。
- 两单**首版不带附件**（附件业务键机制归 ADR 0072 / W4；后续要加复用同形状）。
- 回调三分类（ADR 0067）：`APPROVED` → 2 通过，请假单同事务写扣减流水、加班单同事务写调休入账流水；`REJECTED` → -1；`WITHDRAWN` → -2。同值幂等 no-op，异值抛错回滚。通过后锁定不可重提；拒绝/撤回可改后重提（单据号不变，历史审批保留）。加班入账后不可逆（没有反审批动作），错发用负数发放行冲抵。

### 页面、按钮点与数据范围

- 后台五页（蓝图菜单不变）：`/business/attendance/group`（考勤组与班次 + 节假日区块）、`/record`（打卡记录）、`/repair`（补卡处理）、`/leave`（假期类型与发放）、`/stat`（月度统计）。按钮点：`attendance:group:add|edit|remove`、`attendance:record:repair`、`attendance:type:add|edit|remove`、`attendance:ledger:grant`；读端点只判页面授予。
- 办事：`/work/my-attendance`（打卡）+ 我的申请（请假·加班两页签）+ 考勤记录与假期（当月逐日状态 + 余额）；登录即有，不套后台授权与数据范围，构造上只读本人。
- 数据范围（蓝图 §4）：打卡记录、补卡、发放流水、月度统计按 `sys_user.dept_id`（当前）+ `sys_user.id` 套五档（ADR 0053/0057）；统计下钻与逐日明细同套，不能靠 ID 绕过列表范围。
- **月统计行集合** = 组内启用账号 ∪ 当月有考勤流水的账号；停用账号只出现在有流水的月份——离职移组不抹历史，离职留组也不产生未来缺卡噪音。

### 统计口径

- 月度统计按人：应出勤（按工作日判定公式逐日计）、实出勤（= 应出勤 − 请假天数 − 缺卡天数）、迟到次数、早退次数、缺卡天数、请假按类型分列（天）、加班时长（小时）。
- 逐日状态枚举：正常 / 迟到 / 早退 / 迟到且早退 / 缺卡 / 请假·类型 / 休息日 / 休假日 / 补班日；点人下钻当月逐日明细，与办事侧复用同一推导 service。
- 首版不做 Excel 导出（对齐报销域）。

### 首版不做

排班、弹性工时、多地点、外出、出差（蓝图）；跨天班与跨天加班单；0.5 天/小时粒度请假；单据附件；假期结转与过期自动规则；余额冻结表；Excel 导出；打卡设备、外勤/WiFi/定位打卡；考勤与薪酬联动。

## 表结构草案（不执行）

沿用仓库约定：无外键；公共字段 `create_time`/`update_time`/`is_deleted`；索引单独 `CREATE INDEX`（MySQL/H2 双兼容）。成员与节假日两表为硬删关系/配置，不带 `is_deleted`（见上文）。

```sql
CREATE TABLE attendance_shift (
  id BIGINT NOT NULL AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL,
  start_time TIME NOT NULL,                  -- 上班时刻
  end_time TIME NOT NULL,                    -- 下班时刻，晚于上班，同一天内
  lunch_start TIME DEFAULT NULL,             -- 午休起，可选
  lunch_end TIME DEFAULT NULL,
  grace_minutes INT NOT NULL DEFAULT 0,      -- 迟到/早退宽限分钟
  remark VARCHAR(255) DEFAULT NULL,
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);

CREATE TABLE attendance_group (
  id BIGINT NOT NULL AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL,
  shift_id BIGINT NOT NULL,                  -- 绑定一个班次
  workdays VARCHAR(16) NOT NULL,             -- 每周工作日，如 1,2,3,4,5
  remark VARCHAR(255) DEFAULT NULL,
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE INDEX idx_attendance_group_shift ON attendance_group (shift_id);

CREATE TABLE attendance_group_member (       -- 纯关系表，硬删
  id BIGINT NOT NULL AUTO_INCREMENT,
  group_id BIGINT NOT NULL,
  user_id BIGINT NOT NULL,                   -- sys_user.id，一人最多一组
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  PRIMARY KEY (id)
);
CREATE UNIQUE INDEX uk_attendance_member_user ON attendance_group_member (user_id);
CREATE INDEX idx_attendance_member_group ON attendance_group_member (group_id);

CREATE TABLE attendance_holiday (            -- 全局日历，硬删
  id BIGINT NOT NULL AUTO_INCREMENT,
  holiday_date DATE NOT NULL,
  name VARCHAR(50) NOT NULL,
  day_type TINYINT NOT NULL,                 -- 1 休假日 / 2 补班日
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  PRIMARY KEY (id)
);
CREATE UNIQUE INDEX uk_attendance_holiday_date ON attendance_holiday (holiday_date);

CREATE TABLE attendance_punch (
  id BIGINT NOT NULL AUTO_INCREMENT,
  user_id BIGINT NOT NULL,                   -- sys_user.id，数据范围「本人」列
  punch_date DATE NOT NULL,
  slot TINYINT NOT NULL,                     -- 1 上班卡 / 2 下班卡
  punch_time DATETIME NOT NULL,              -- 服务器时间
  source TINYINT NOT NULL,                   -- 1 网页打卡 / 2 补卡
  operator_user_id BIGINT DEFAULT NULL,      -- 补卡操作人；网页打卡为空
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE INDEX idx_attendance_punch_user_date ON attendance_punch (user_id, punch_date);
CREATE INDEX idx_attendance_punch_date ON attendance_punch (punch_date);

CREATE TABLE attendance_leave_type (
  id BIGINT NOT NULL AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL,
  balance_required TINYINT NOT NULL DEFAULT 0,   -- 1 需要余额
  overtime_credit TINYINT NOT NULL DEFAULT 0,    -- 1 加班入账目标（全局唯一）
  status TINYINT NOT NULL DEFAULT 1,             -- 1 启用 / 0 停用
  sort_no INT NOT NULL DEFAULT 0,
  remark VARCHAR(255) DEFAULT NULL,
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);

CREATE TABLE attendance_leave_ledger (
  id BIGINT NOT NULL AUTO_INCREMENT,
  user_id BIGINT NOT NULL,
  leave_type_id BIGINT NOT NULL,
  entry_type TINYINT NOT NULL,               -- 1 发放（可负调整）/ 2 扣减（恒负）/ 3 加班入账（恒正）
  change_hours DECIMAL(10,2) NOT NULL,       -- 签好数值，余额 = Σ(change_hours)
  business_type VARCHAR(64) DEFAULT NULL,    -- attendance.leave / attendance.overtime
  business_id BIGINT DEFAULT NULL,
  operator_user_id BIGINT DEFAULT NULL,      -- 发放操作人；回调写入为空
  remark VARCHAR(255) DEFAULT NULL,
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE INDEX idx_attendance_ledger_user_type ON attendance_leave_ledger (user_id, leave_type_id);
CREATE INDEX idx_attendance_ledger_business ON attendance_leave_ledger (business_type, business_id);

CREATE TABLE attendance_leave (
  id BIGINT NOT NULL AUTO_INCREMENT,
  applicant_id BIGINT NOT NULL,              -- sys_user.id
  leave_type_id BIGINT NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  days INT NOT NULL,                         -- 提交时按日历折算定稿（休假日剔除）
  hours DECIMAL(10,2) NOT NULL,              -- 提交时按班次日工时定稿，扣减与在途预计的依据
  reason VARCHAR(255) DEFAULT NULL,          -- 提交时必填
  status TINYINT NOT NULL DEFAULT 0,         -- 0 草稿 / 1 审批中 / 2 通过 / -1 拒绝 / -2 撤回
  submit_time DATETIME DEFAULT NULL,
  finish_time DATETIME DEFAULT NULL,
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE INDEX idx_attendance_leave_applicant_status ON attendance_leave (applicant_id, status);
CREATE INDEX idx_attendance_leave_dates ON attendance_leave (start_date, end_date);

CREATE TABLE attendance_overtime (
  id BIGINT NOT NULL AUTO_INCREMENT,
  applicant_id BIGINT NOT NULL,
  overtime_date DATE NOT NULL,
  start_time TIME NOT NULL,
  end_time TIME NOT NULL,                    -- 晚于开始，同一天内；跨天拆两天提交
  hours DECIMAL(10,2) NOT NULL,              -- 服务端计算
  reason VARCHAR(255) DEFAULT NULL,
  status TINYINT NOT NULL DEFAULT 0,         -- 同 attendance_leave
  submit_time DATETIME DEFAULT NULL,
  finish_time DATETIME DEFAULT NULL,
  create_time DATETIME DEFAULT NULL,
  update_time DATETIME DEFAULT NULL,
  is_deleted TINYINT NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);
CREATE INDEX idx_attendance_overtime_applicant_status ON attendance_overtime (applicant_id, status);
CREATE INDEX idx_attendance_overtime_date ON attendance_overtime (overtime_date);
```

## 种子草案（不执行）

- `sys_menu`：目录 `/business/attendance`、五页与上述按钮点；办事入口「我的考勤」；补授 `super_admin`，保持幂等。
- `attendance_leave_type`：五项预置（年假/事假/病假/调休/婚丧产假），由迁移种。
- `oa_business_template`：`attendance.leave`、`attendance.overtime` 各映射到一份已发布审批模板；模板审批人用部门负责人（ADR 0065/0069），单节点线性。
- 演示班次（如 9:00–18:00 午休 12:00–13:00）、演示考勤组、当年节假日、年假发放示例由部署/演示种子准备，迁移不种业务数据（对齐 ADR 0072）。
- 迁移编号取实现票届时的下一可用版本（main 当前最高 V120）；H2 合同测试跑真迁移；索引建完用实发计划验（#185 教训）。

## 考虑过的替代方案

- **每日考勤日报表落库**：统计聚合最简单，但打卡/补卡/请假回写/冲正四处都要同步写日报，正是两态分离要避免的多处真相；读时推导规模无压力。
- **不做节假日日历**：国庆全员算缺卡、应出勤虚高，真跑判据不可接受；按组各自配例外日 = N 组 N 份日历，全局表最小。
- **考勤组按部门圈人**：部门归属漂移会牵动打卡规则与统计，直接选人是一份诚实的名单。
- **余额用快照字段（人 × 类型一列）**：发放/扣减/回调/纠错每处都要改快照，并发与冲正两处真相；账本一行一流水可重算、可审计。
- **假期类型走字典**：字典只有值/标签/排序，装不下「是否需要余额」「加班入账目标」这类行为配置。
- **统一按天记账（加班满 4h 折 0.5 天）**：加班余数丢失、规则生硬；统一按小时一条规则全覆盖，页面按天展示。
- **每类型自带计量单位**：最灵活但配置最多，小团队用不上。
- **提交不校验余额、审批通过时校验**：矛盾推给审批人，且余额校验失败无法顶回「通过」动作，会卡死审批事务。
- **在途用冻结表**：单据「审批中」状态本身就是冻结，冻结表是第二真相。
- **请假支持 0.5 天**：起止半天标志让折算复杂度翻倍，首版整天。
- **补卡走审批**：蓝图已裁决后台直改 + 审计日志。
- **统计落统计表**：小团队派生查询足够，多一张表多一处同步（对齐 ADR 0072）。
- **加班单与打卡记录交叉校验**：休息日加班本就无班可打，校验只添堵；加班时长以单据为准。
