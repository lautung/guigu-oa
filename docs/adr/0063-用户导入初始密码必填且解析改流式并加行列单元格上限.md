# 用户导入：初始密码必填，解析改流式并加行列单元格上限

#263 的用户导入有两个安全缺口：模板没有密码列，服务端把所有导入用户的密码统一写成已知常量 `123456`；解析用 `XSSFWorkbook` 一次性装载整本工作簿，2MB 文件可以在极远的稀疏单元格（例如第 1048576 行、最后一列）上把线程内存按维度放大。本票把密码变成导入动作的参数，并把解析换成事件模型 + 硬上限。

决定：

- **初始密码是动作参数，不是数据列**。`POST /admin/system/sysUser/import` 的 multipart 增加 `initialPassword` 字段；必填、长度 6–100（与重置密码/注册同一策略），缺失/空白/越界整批 201 命名拒绝。服务端删除 `DEFAULT_IMPORT_PASSWORD` 常量，静态扫描不再出现固定初始口令。
- **BCrypt 每批只算一次**。同一批用户的明文相同，复用同一个 BCrypt 哈希；1000 行不再重复编码。每行仍是独立 `saveUser` 事务，失败行不写、成功/失败汇总不变。
- **响应与日志不回显密码**。导入结果 VO 不新增密码字段；操作日志的参数脱敏从「字段名黑名单」扩到「参数名黑名单」，裸 `initialPassword` 参数落 `***`（`OperParamSanitizer.sanitize(args, parameterNames)`）。
- **解析改流式**：`OPCPackage` + `XSSFReader` + `XSSFSheetXMLHandler`（SAX）逐行产出，不构建 `XSSFWorkbook`/整表单元格图。只保留表头校验、当前行转换与汇总。
- **上限集中定义在 `SysUserExcelService`**：文件 2MB（保留）、非空数据行 1000（保留）、最大列数 20（模板 7 列 + 余量）、数据区单元格总数 20000（1000 × 20 的边界值，表头不计）。任一超限整文件 201 拒绝，不做部分导入；空行仍跳过且不计入行数。文案区分行/列/单元格与维度越界。
- **模板列与导出列保持完全一致**（用户名、姓名、部门、岗位、手机、状态、创建时间），不新增密码列；密码是导入动作参数，不是用户数据列。
- **逐行校验顺序不变**：用户名必填/长度/唯一、姓名必填/长度、手机长度、状态解析、部门/岗位存在且启用；非业务运行时异常记为该行失败并继续。
- **安全套件新增四类真实 multipart 拒绝**：缺少初始密码、过短初始密码、稀疏远单元格、21 列；现有类型/大小/畸形/缺字段用例保留。稀疏/宽表载荷用仓库内无依赖的最小 xlsx 生成器（STORE ZIP + inlineStr）构造，不落二进制夹具。

规格内的两处取舍（票面自相矛盾，按更具体的决策/测试口径落地）：

- **列上限取 20 而不是 7**。User Story 10 写「列数超过模板列数就拒绝」，但 Implementation Decisions 与 Testing Decisions 都写「最大列数 20（模板 7 列 + 余量）」「20 列边界通过/21 列拒绝」。采用后者：8–20 列沿用旧行为忽略（不进入用户记录，也不夹带未校验数据），21 列起整文件拒绝；「隐藏列不夹带数据」的意图由「不读入业务字段」保证，而不是由 7 列硬拒保证。
- **密码校验在方法安全 gate 之后**。导入没有 `@Valid` DTO，`initialPassword` 是 `@RequestParam`，校验在 service 内；无权限请求统一 205，不因参数形状改变拒绝码。这与 ADR 0034「配置写 DTO 校验先于 gate」不冲突：那条顺序来自 `@Valid` 在参数解析期的位置，作用域是配置写请求体。
- **「每行 BCrypt」按「每行独立保存路径」理解**：每行仍是独立事务与独立失败隔离，但同一批共享一次 BCrypt 编码（明文相同，盐复用不降低强度；1000 行从 1000 次编码降到 1 次）。

考虑过的替代方案：

- **模板加密码列**（否决）：破坏「模板列 = 导出列」的产品约定，导出会把密码列带出去或需要额外裁剪；同一文件里不同行不同密码也不是这次要的语义。
- **随机密码并回显**（否决）：密码进响应/页面/日志，等于把固定口令换成一次性明文泄漏；分发渠道是另一张票。
- **先读 `dimension` 再决定是否装载**（否决）：`dimension` 是文件自述、可伪造；`XSSFWorkbook` 仍会按单元格图分配内存，只有事件模型能避免。
- **超限只截断前 N 行**（否决）：会出现「前 N 行成功、后面静默丢弃」，与部分成功汇总的语义冲突；整文件拒绝更可解释。
- **异步导入/临时文件**（否决）：超出本票范围，且引入任务状态与清理面。

后果：

- 服务端无数据库迁移；`lautung-oa-auth` 新增 `UserImportSheetReader`（包内），`SysUserExcelServiceImpl` 不再持有 `XSSFWorkbook` 导入路径。
- `OperParamSanitizer` 增加带参数名的重载；`OperLogAspect` 从 `MethodSignature` 取参数名（父 pom 显式钉住 `maven.compiler.parameters`，合同测试断言明文不落库）。未来任何裸敏感参数都走同一层。
- 客户端导入弹窗新增必填「初始密码」（6–100 位，本地预检与服务端同文案），提交载荷增加 `initialPassword`；弹窗不再展示固定口令。
- 安全套件从 5 条扩到 9 条用户导入拒绝用例；`docs/test/plan/security-cases.md` 的 61 条定向矩阵不变（这 4 条在 Playwright 安全 spec 里）。
- 1000 行导入的 BCrypt 成本从 1000 次降到 1 次；行/列/单元格上限在写库前拒绝，仍然不做全量回滚。
