# 模板编辑拥有强制离开判定，占用只作为端口注入

模板编辑的“这一次打开是否还能继续”由编辑 module 判定：module 在每次离开判定时实时查询一个占用端口（`allow | redirect` 及目标地址），并用认出结果判断进入身份是否仍属于本次打开；页面保留 resize、focus、token 与菜单变化的事件接线，只调用 `environmentChanged()`，不再自行计算 `mustLeave`，也不再直接调用 `release()` 执行离开。强制离开（占用不成立、进入身份被替换或本次打开已释放）优先于普通离开确认；若此时有确认框在等待，module 通过 confirm adapter 的 `dismiss()` 关闭它，迟到的确认结果不得再次导航。占用仍是 surface 的规则，module 只消费“能不能占用”这一事实，不读 viewport、菜单或路由。

公开 interface 收缩为 `requestLeave(): Promise<boolean>`（true 表示本次打开已释放，路由可以继续）、`environmentChanged(): Promise<void>`、`back()` 与 `dispose()`；`requestLeave` 不再接受 `force`，`state.isCurrent` 删除。`dispose()` 只用于页面卸载清理，不再作为“立即离开”的手段。占用不成立时的目标地址由端口给出；进入身份被替换且新身份仍存在时，module 用 `replace` 导航到 `getDefaultPostLoginRoute()`，身份已清空时只释放、不导航，把登录跳转留给认出流程。强制导航使用 `replace`，避免返回键回到已经失效的编辑页。

页面继续拥有事件来源：resize、focus、token 与菜单 watch 都调用 `environmentChanged()`，module 不订阅 DOM 或 store。策略因此只在 module 一处，事件接线仍在 view 层；新调用方必须接上路由守卫与环境事件，但不会再把强制条件抄一遍。路由守卫传入的普通离开仍由 module 决定是否确认，占用不成立时同一次调用直接释放并返回可离开，导航目标仍由发起这次导航的一方决定。

否决的替代方案：保留 `requestLeave(force)` 会把“何时强制”留在页面，候选 4 指出的泄漏不变；把强制离开上移到 `ClientSurfaceHost` 或路由层会让编辑器未保存内容的丢弃语义进入 surface，并与 ADR 0005 的“离开行为由编辑 module 决定”冲突；让 module 自己订阅 resize、focus、token 与菜单会为一个调用方引入订阅生命周期，收益不足。分配角色 module 的同类 `requestLeave(force)` 不在本次范围，两个配置 module 暂时不一致，等两边生命周期都稳定后再评估共享。

合同测试新增占用 redirect、强制离开抢在进行中的确认、身份替换与身份清空、环境未变不打断、保存中强制离开五类；现有端到端用例的“缩成手机”和“身份被替换”继续证明页面接线，不新增浏览器用例。ADR 0005 仍是模板编辑生命周期的总体决策，本 ADR 只把其中“离开行为由 module 决定”落到 interface。
