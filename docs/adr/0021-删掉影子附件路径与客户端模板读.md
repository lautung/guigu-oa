# 删掉影子附件路径与客户端模板读

候选 8 是 deletion test 直接通过的清理：`AttachmentSection.vue` 没有任何引用，却是 `api/attachment.ts` 的唯一消费者；`config/process-template.ts` 的客户端 `read()` 生产无人调用，只有两个单测在维持；`api/process.ts` 的 `show` / `approve` / `startUp` 早已被 `approval-detail-http` 与 `approval-start-browser` 的 scoped request 取代，只剩 `StartProcessRequest` 类型和 `getCurrentUser` 仍被使用。现在删除 `AttachmentSection.vue`、`api/attachment.ts` 与 `api/process.ts`；`StartProcessRequest` 移到 `types/domain.ts`，`work/profile.ts` 增加 `readProfile(request)`（内部用现有 `getCurrentUserRequest` 与 `presentProfile`），基本信息页改用它并把加载状态留在页面；客户端 `read()` 与只被它使用的私有 `presentForm` 一并删除。

有意不抽共享附件 UI：发起页的附件区管理草稿、可用性与替换/中断上传，详情页负责发起后补传与下载授权，两者行为不同；删掉影子实现后不存在第二个消费者，抽一层组合只会为想象中的复用增加 interface。将来出现第三个附件界面时再评估。服务端 `ApprovalTemplate.read` 仍是审批模板展示与发布的权威，客户端只是不再保留一份平行的读取实现。ADR 0002/0012 的附件次序、回滚与 wire contract 都不受影响，本 ADR 不新增 interface。

测试随之收敛：`process-template.spec.js` 删除 `read` 的两个用例，`profile.spec.js` 增加 `readProfile` 的请求构造与呈现用例；`AttachmentSection` 与 `api/attachment` 原本没有测试。客户端 382 个单测（删 2 个 `read` 用例、加 2 个 `readProfile` 用例，总数不变）、`vue-tsc`、ESLint、Prettier、`build:prod` 与 e2e 全绿；服务端不改，不重跑服务端测试。

Related: ADR 0002（附件直传挂审批实例）；ADR 0012（附件回滚补偿）；ADR 0020（路径收口）。
