# 配置写请求补长度与格式约束

#152（ADR 0034）把配置写请求收成 DTO 并拦空，但只覆盖「为空」。字段越界在 MySQL 严格模式下走 `GlobalExceptionHandler` 的兜底分支，返回「执行全局异常处理...」而不是可读文案（合同测试在 H2 上同样复现——H2 也按列宽拒绝）；`sys_menu.type` 的非法取值借道 `ConfigurationGrant` 的配置节点判定（只认 0/1），以「只能维护配置菜单」拒绝，与「类型非法」不是同一件事；类型 1（菜单页）不带组件路径也能落库，服务端既不补默认值也不判。

决定：

- 长度上限对齐列宽，全部落在请求 DTO 的 `@Size` 上：用户 `username`/`name`/`phone` 20，角色 `roleName`/`roleCode` 20、`description` 255，菜单 `name` 50、`path`/`component` 200、`perms`/`icon` 100，审批类型 `name` 50、`description` 255，审批模板 `name` 50、`iconUrl`/`processDefinitionPath` 200、`processDefinitionKey` 100、`description` 255。`formProps`/`formOptions` 是 TEXT 列，不设上限。密码不设 `@Size`：请求体里是明文，落库前一律 BCrypt（60 字符），列宽 100 不会越界。
- `sys_menu.type` 只收 0/1（`@Min`/`@Max`，文案「菜单类型只能为 0 或 1」），在校验边界拒绝，不再借道授予闭包。
- 菜单页必须自带组件路径，按两条缝判：save 在 DTO 上判死（`@AssertTrue`：type=1 时 `component` 必须非空白）——创建时无从回读旧行，这是纯请求形状；update 在 `updateMenu` 的 service 里按落库形状判——请求不发 `component` 即沿用旧行，目录转成菜单页而旧行组件为空仍要拒。判定面是落库后的最终形状，因此存量坏行（类型 1、组件为空）在补上组件前，任何更新都会被拦，这是有意的不落坏数据。显式送空白组件在 DTO 拒（空白会按 MyBatis-Plus 的非空策略覆盖旧行）。消息统一「类型为菜单时组件路径不能为空」。不补默认值：组件路径是页面身份，替它猜默认值会把坏数据变成好数据的样子；目录填 `Layout`/`ParentView` 是客户端表单的事（#157）。

## 考虑过的替代方案

- **在 service 里统一判长度与类型**：可行，但顺序上落到配置 gate 之后——未授予用户提交越界体会得到 205 而不是字段文案，破坏 ADR 0034 定下的「静态形状先于 gate」。
- **类级自定义约束表达 type 与 component 的联动**：要新增一套 `@Constraint` 基建，仓库零先例；`@AssertTrue` 是 jsr303 标准形状，消息能进同一套「按字段名排序、`；` 连接」的拼接。
- **update 也要求 component 必填**：update 的语义是「不发即不覆盖」，页面改名这类局部更新会平白 201；只拒显式清空，未发送的沿用旧行由 service 兜住。
- **顺手给 `status`（0/1）与 `updateStatus` 路径变量加约束**：`status` 越界不触发 DB 兜底（TINYINT 装得下，语义上等同非 1 的停用侧）；`updateStatus/{id}/{status}` 是路径参数不是请求体，超出本轮「配置写请求体」的范围。

## 后果

- 越界/非法取值都有具体中文 201 文案；接口套件在真 MySQL 栈上证明不再落「执行全局异常处理...」。
- `@AssertTrue` 的 getter 以属性名参与全局排序：`pageComponentFilled` 排在 `name` 之后、`parentId` 之前；空体的消息不变（type 为空不触发组件规则）。
- 既有负例载荷适配：`FlywayMigrationContractTest` 两处 type=1 的 save 载荷补 `component`（保护与 gate 分支不被边界遮蔽）；接口套件 B19 的 type=2 用例改钉边界文案，B22 良构体补 `component`；栈回归 p1-3 建菜单补填组件路径。客户端 `formForCreate` 默认 type=1 加空组件，本地必填规则是 #157 的事，期间该表单提交空组件会得到明确的 201 提示。
- 未做：菜单/用户/角色 `status` 的取值范围、手机号格式（长度已拦）、`updateStatus` 路径变量、`RefreshTokenVo` 的必填（#155）、`batchRemove` 空列表语义（#156）、客户端配置表单的本地必填规则（#157）。
- 回归锚点：`RequestValidationContractTest`（越界/类型/组件文案与组合排序）、`FlywayMigrationContractTest`（真授予下保护与 gate 分支 + 目录转菜单）、`SysMenuServiceImplTest`（落库形状判定）、接口套件 `tests/api/b-user.spec.ts`（B23）、`b-role.spec.ts`（B24）、`b-menu.spec.ts`（B19/B22/B25）、`c-process-config.spec.ts`（C15）、栈回归 `p1-3-config-crud.spec.ts`。
