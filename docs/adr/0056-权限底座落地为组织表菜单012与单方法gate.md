# 权限底座落地为组织表、菜单 0/1/2 与单方法 gate

ADR 0052 把权限收成页面授予、按钮点与数据范围三层，ADR 0053 定了数据范围的原则；#210 把两层原则落成可实现的形状。侦察发现三处与票面假设不一致：组织表完全不存在（`sys_user.dept_id`/`post_id` 是孤立列）；`sys_menu.type` 的实体注释、种子与代码三处口径不一致；授予闭包仍留着固定三根白名单与若依旧组件的排除逻辑。本条只钉后台权限的表、菜单、gate 与种子；数据范围的值对象见 ADR 0057，`/info` 合同见 ADR 0058。

决定：

- **组织表新建**：`sys_dept`（`parent_id`、`ancestors`、`name`、`leader`、`sort_value`、`status` + 公共字段）、`sys_post`、`sys_user_post`（多岗位）、`sys_role_dept`（自定部门）。复用 `sys_user.dept_id`（单部门），删除孤立的 `post_id`（无数据）。`ancestors` 存**含自身**的包裹逗号路径：部门 5 在 3 下为 `,0,3,5,`，根为 `,0,1,`；「本部门」= `id = ?`，「本部门及以下」= `ancestors LIKE '%,3,%'`。部门被删/停用时按当前树解析，不做历史快照。
- **角色数据范围列**：`sys_role.data_scope` 五档 `1..5`，新角色默认 `5`（仅本人）；种子 `config_admin` 设为 `4`（本部门及以下）作受限样本。
- **菜单表值域**：`sys_menu.type` 收成 `0` 目录 / `1` 页面 / `2` 按钮。按钮行 `parent_id` 必须是页面，`perms` 必填且唯一，`path`/`component` 为空；写接口 DTO 接受 `2` 并要求 `perms`；修正实体注释与 ADR 0036 的值域。**不加 `visible` 列**：隐藏页仍是「页面挂在页面下」的结构推导，但授予闭包只保留「可见祖先页面也被授予」的隐藏页——隐藏页自身不能单独构成后台权限。
- **`sys_menu` 全表即后台**：删除闭包里的固定三根白名单（`/system`、`/processSet`、`/processMgr`）与 `work`/`wechat`/`dashboard`/`onlineprocessset` 排除逻辑（V1 种子本就没有这些行，是历史防御残留）。目录允许嵌套（如系统管理下的日志管理）；一级导航 = `type=0` 根 + 客户端内置的工作台/办事，工作台与办事不由 `sys_menu` 表达。
- **审批两棵树迁入系统管理**：`/processSet`、`/processMgr` 两个根改为 `/system` 下的目录，path 变相对段 `processSet`/`processMgr`，页面绝对路径随之变 `/system/processSet/...`、`/system/processMgr/...`，`component` 不变。14 个 process 相关 gate 字面量、客户端路由、e2e 一次性迁移，不留两套路径规则。
- **单方法 gate**：`@PreAuthorize("@backofficeGate.isAllowed('<页面绝对路径>','<权限标识>')")`；读端点只传页面路径（页面授予覆盖读），写端点再传按钮点。判定顺序页面先、按钮后，两处都回 HTTP 200 + code 205「没有操作权限」。bean 从 `configurationMenuGate` 改名 `backofficeGate`，现有 35 处注解机械替换；控制器不重写。
- **权限标识命名**：`<模块>:<对象>:<动作>`，模块按业务域（`system`/`process`/`monitor`/`tool`），对象用短名（`user`/`role`/`menu`/`dept`/`post`/`dict`/`config`/`notice`/`type`/`template`/`instance`），动作 `add`/`edit`/`remove`/`export`/`resetPwd`/`assignRole`/`clean`/`unlock`/`forceLogout`/`publish`/`upload` 等。状态切换并入 `edit`；读不设 `:list`/`:query`。页面路径与权限标识解耦：`/system/sysUser` 的按钮是 `system:user:add`。
- **种子与补授**：新迁移建 `super_admin`（`data_scope=1`），insert-select 授予**当时**全部目录/页面/按钮；`admin` 解除 `config_admin`、改挂 `super_admin`；`config_admin` 保留为受限样本，本波不赋给任何用户。之后每个模块迁移自己给 `super_admin` 补授新增页面与按钮——管理员不做身份旁路，新增菜单不显式授予连管理员也看不见。本波只种现有 6 个页面的按钮点；未实现页面的菜单行由各自模块票补，避免死链。
- **合同测试**：只授目录、只授按钮、隐藏页单独授予、按钮点缺失 205、校验先于 gate、按钮点的父页面路径与注解第一参数一致、每个后台写端点都声明按钮点。

考虑过的替代方案：

- **加 `visible` 显式列**（否决）：隐藏规则已经在结构推导里跑通并有测试，加列等于把同一条规则写两遍。
- **保留三根白名单并继续扩张**（否决）：新后台有五组以上一级目录，白名单会变成每次加页面都要改的常量；`sys_menu` 全表即后台更简单。
- **按钮点只在 service 或拦截器里判**（否决）：控制器注解是现有 35 处的形状，service 判定会让页面/按钮顺序散到各处，且无法用一次机械替换完成迁移。
- **`super_admin` 代码特判或每次迁移重授全量**（否决）：等于身份旁路，ADR 0052 特意把硬编码管理员拿掉；显式补授让授权 bug 在管理员身上也能暴露。
- **保持两棵审批顶层树**（否决）：与蓝图 §8 的目标菜单树冲突，顶部会多出两组；只改 `parent_id` 不改 path 则同一棵树混用绝对/相对两套规则。

后果：

- ADR 0013 的「不引入按钮/动作权限」由 ADR 0052 取代，本条落成实现；ADR 0014 的闭包输出扩为页面 + 按钮；ADR 0036 的 `type` 值域扩为 `0/1/2`。
- 现有 6 个页面补按钮点，35 处 gate 注解改 bean 名，14 处 process 路径改写；客户端路由与 e2e 同波更新。
- 新后台页的模板：菜单行 + 按钮点 + 模块迁移补授 `super_admin` + 控制器单方法 gate + 合同测试，缺一项即视为未完成。
- 部门/岗位/用户 CRUD 页面不在本条，但它们的表由本条建；演示授权矩阵等组织页面票再种。
