# 产品形态改为桌面优先的泛 OA 后台，撤销统一客户端约束

云尚办公原本按「审批为核的统一客户端」设计：办事必须能在手机完成，配置页在手机或未授权时回落到待处理，全站只有一个窄表面。2026-11-02 的产品重画把目的地改成**桌面优先的泛 OA 后台**：审批保留为一个模块，围绕它长出系统管理、组织、审计、公告、监控与工具；功能清单与交互范式参照若依分离版 Vue3，代码一律自研。

决定：

- 产品名保留「云尚办公」。它是长期自用的产品，不是某个课程项目的管理端/员工端。
- 撤销统一客户端的全部形态约束：办事不再要求必须手机完成；不再有「配置页占用」与手机回落；不再用「办事/配置」两组限定内容密度。
- 手机改为全面响应式：所有页面可打开；审批完整可用；表单设计器、流程上传、授权树、图标选择这类重交互页同样可编辑，只在顶栏提示「建议桌面」。不做只读墙。
- 外壳改为多标签页 + 混合导航：顶部放一级（工作台/办事/系统管理/系统监控/系统工具），左侧放二级；工作台固定标签，可关闭当前/其他/全部标签；标签只存路径与标题，不做组件缓存（列表页每次激活重读，避免与 ADR 0009/0018 的读状态、`release()` 语义打架）；手机宽度隐藏标签栏，侧栏收进抽屉。
- 登录落点统一为工作台：首卡显示待处理数与近期审批量，直达待处理/发起；不按权限分流落点，也不落静态介绍页。
- 审批仍是业务核心，但只是后台的一个模块：办事组（发起审批/待处理/已处理/已发起/抄送我的/基本信息）内置、登录即有；审批设置与审批实例查询作为后台页挂在系统管理下。
- 通知口径：待处理仍是任务通知的唯一来源；公告是全员广播 + 已读回执，顶栏铃铛只报公告未读；不做站内信、待办铃铛与定向发布。
- 组织模型：部门与岗位只作组织数据与用户归属；审批链继续由 BPMN 指定用户名，本轮不让部门/岗位成为任务分配依据——改 `candidateGroups` 会牵动成员资格证据、待处理读、认领动作与写侧，等于重做审批核心的一块。
- 能力边界与优先级见 `docs/spec/泛OA后台产品蓝图.md`：P0 外壳/权限底座/组织/字典/参数/审计/审批迁入；P1 公告/在线用户/监控/个人中心/接口文档；P2 数据监控/定时任务/表单构建；不做注册页、在线代码生成器、i18n、多数据源、Druid 控制台、硬编码管理员。

考虑过的替代方案：

- **保持单外壳与手机回落**：把后台继续当作配置页的延伸，桌面后台体感立不起来；占用规则还会让每个新页面都背一套 surface 判定。
- **手机只保留审批**：与用户选定的「全面响应式」相反；只读墙会让手机上连一条公告都改不了。
- **纯单页无标签**：少一层交互，但失去后台最核心的桌面范式，与参照若依的目标不符。
- **按权限分流登录落点**：两套落点行为，文案与测试都要分叉。
- **部门/岗位进审批链**：与「不重做审批核心」冲突；等真有按组织分配的诉求，单独立票。

后果：

- ADR 0010/0015 的占用端口与「变成手机尺寸强制离开」作废；编辑 module 仍拥有离开判定，触发只剩身份替换与本次打开已释放。
- GLOSSARY 的「统一客户端」「配置」「菜单组」「占用」删除，「后台」「后台页」「工作台」新增。
- `ClientSurface` 从「占用/密度/返回路径」缩成响应式判定；配置页的隐藏父级逻辑并入后台菜单授予。
- 新后台页必须复用 `createListRead`/`createListPage`（ADR 0009/0018），不得各写一套读状态。
- 新增的公告富文本是独立渲染面，由公告票另立消毒 ADR，不推翻 ADR 0028（审批表单值只按文本）。

Related: ADR 0010/0015（占用与手机强制离开被取代）；ADR 0009/0018（列表读收口继续有效）；ADR 0028（表单值文本化，不受公告影响）；issue #206/#207/#208。
