# 分配角色保留不确定结果，权限刷新独立恢复

分配角色的读取、勾选、可保存条件与结果归属由前端一个完整 module 管理，保留现有后端协议和权限含义，角色本身的增删改及角色菜单授予另行处理。未保存勾选只属于本次打开，普通关闭、切换用户或离开前确认丢弃，刷新不恢复；身份失效、失去配置权限或变成手机尺寸时按现有规则直接离开。

保存提交后冻结本次用户与角色选择并阻止重复提交，允许确认后关闭或离开，离开不撤销保存；迟到结果只归原操作，不关闭新的弹窗或抢占后续页面。现有保存全量替换角色，没有版本或请求标识；通用错误也不足以证明未写入，因为提交后的权限缓存失效仍可能出错。因此超时、断网或其他无法证明未写入的结果保留为“分配结果待确认”，保留本次提交内容、暂停再次保存并提供重新读取供核实，不凭角色集合相同推定原请求成功，接受人工核实的成本。只有明确认证过期响应保留既有的至多一次认证恢复重试，其他不确定结果不自动重发。

已提交但未确认的记录按本浏览器标签页、当前进入身份和目标用户保留，普通关闭和刷新不丢失；刷新后失去原响应归属的在途记录按待确认恢复，不自动重发。重新打开同一用户不能绕过保存限制，其他用户可正常分配；无法可靠保留记录时先不发出保存。这个限制只约束本标签页，不提供跨标签页协调或后端并发冲突检测。

本标签页仍可观测到请求在等待响应时，不允许结束本次分配；进入待确认后提供重新读取供核实，允许用户明确“结束本次分配”，但结束前说明原保存仍可能生效并影响后续分配。结束只清理本地记录，不判定原保存失败，也不恢复原提交内容为可再次保存的勾选；后续分配必须重新读取最新角色。

明确保存成功后重新认出当前操作者，以覆盖给自己分配角色的情况；同一进入身份下，即使已离开原弹窗，迟到成功仍刷新资料与菜单，但不弹旧提示、不关闭新弹窗、不跳回旧页面。只有当前页面已失去配置资格时，才按现有占用规则离开配置；身份已更换则不操作新用户。权限刷新失败独立恢复，不改变已保存结论，也不重新提交分配角色。

正式 interface 是一次完整“分配角色”：页面读取只读状态，表达打开、勾选、保存、重新读取、结束待确认和请求离开的意图，由 module 统一决定操作资格与结果归属。提交归属与弹窗展示归属分别管理，页面不自行配对用户和角色，也不自行判断保存是否生效；完整行为形成 depth，归属和恢复规则集中带来 locality，页面与测试共用 interface 获得 leverage。传输、提交记录和认出配合作为内部 adapter，生产实现与可控测试实现通过同一个 seam 使用完整行为。

正式合同测试跨上述 interface，覆盖 A→B 迟到读取、重复保存、关闭重开、刷新恢复、结束待确认、身份替换和权限刷新失败，并验证读取失败不能保存、合法空角色列表可以保存。浏览器测试使用真实弹窗、勾选和导航，配合受控响应验证完整交互、提交内容及恢复行为；这些证据只证明客户端配合，不证明后端持久化或真实权限正确性，后者继续由真实后端合同验证。
