# refresh 失败按认证家族返回 401 与 208

`POST /admin/system/index/refresh` 是认证路径上失败形状最杂的端点：`refreshToken` 缺失、空白或不可用走 `readRefreshToken` 的 null 分支得到 **HTTP 200 + code 208**（匿名端点不经过过滤器，MVC 返回值没有状态语义）；完全没有请求体撞上 `HttpMessageNotReadableException` 得到 200+201「请求体格式无效」；停用用户得到 200+209。哪个形状取决于 `JwtHelper` 对空值的实现细节，不是任何声明的契约（#155）。而认证家族自 #145 起的契约是「认证失败 = HTTP 401 + code 208/209」（`TokenAuthenticationFilter`、入口点、登录空凭证均如此），客户端 `request.ts` 的注释也按这个契约写死。

决定：refresh 的失败语义是认证失败，不是表单错误。缺失（无请求体、`{}`）、空白与一切不可用（畸形、过期、篡改、类型错、身份不符、已吊销）的 refreshToken 统一 **HTTP 401 + code 208「认证失败」**；停用用户 **401 + 209**；成功保持 200。实现上 `refresh` 改为 `@RequestBody(required = false)` + `ResponseEntity`：无请求体与 `logout` 用同一个匿名端点模式落进 null 分支，失败由控制器显式写出 401，不再借道 200 业务信封。

- 不给缺字段发明 201 字段文案（ADR 0033/0034 的静态形状路线）：请求体只有 `refreshToken` 一个字段，字段缺失等于没有凭证。客户端对 refresh 失败只有一条路径——结束会话：208 归 `invalid`（forget + 回登录页）；201 会归 `retryable`，对终端用户 toast 一条无法自救的字段文案，且会话留在半死状态。
- 客户端配套：`refreshAccessToken` 用裸 axios、不走响应拦截器，401 会被 `transportFailure` 归为 `retryable`；catch 与 #145 主拦截器共用同一个信封判定（4xx 带业务信封按 `businessFailure` 分类，`businessEnvelope` 谓词两处共享），保持 `invalid`/`disabled`，与既有 2xx 信封失败走同一条清会话路径。
- 畸形 JSON（解析失败）不动：仍走 `GlobalExceptionHandler` 的 200+201「请求体格式无效」（ADR 0033 全局规则）。它的主体是「形状无效」而不是「凭证缺失」，`logout` 同样暴露在这条规则下，单独给 refresh 换形状需要动全局 handler。

## 考虑过的替代方案

- **缺失/空白给 201 + 「refreshToken 不能为空」**（ADR 0033 注解路线）：引入 jsr303 + `@Valid` 表达约束不难，但它把「没有可认证的会话」表达成表单错误；客户端归为 `retryable`，每个后续请求再各触发一次失败 toast。登录在 ADR 0033 已对空凭证做了同样的语义选择（401+208），refresh 没有理由更「表单」。
- **保持 HTTP 200 + code 208 只补测试**：契约能钉住，但认证失败返回 200 与 #145 的状态契约（认证失败必须是真实 401）直接冲突，按状态码看监控的网关会把它当成功；既然合同测试必须改，改到位。
- **把畸形 JSON 也收进 401+208**：需要控制器加局部 `HttpMessageNotReadableException` 处理或改全局 handler，动 ADR 0033 的全局规则；收益只有「认证端点内形状完全一致」，目前没有消费者依赖这个差异。
- **把 refresh 搬进过滤器（与 login 对称）**：要重排匿名白名单与 MVC 结构，收益只有复用 `ResponseUtil`；控制器 + `ResponseEntity` 足够。

## 后果

- refresh 失败的 HTTP 状态从 200 变 401：按状态码监控的消费方看到真实认证失败；接口套件 A2 与安全扫描只断言 `body.code`（208/209 不变），不受影响。
- 无请求体从 200+201「请求体格式无效」变为 401+208：匿名端点把「没有凭证」还给认证语义，与 `logout` 的宽松模式对齐。
- `IndexController.refresh` 成为仓库第一个按结果返回不同 HTTP 状态的 MVC 方法（`ResponseEntity`）；其余端点继续直接返回 `Result`。
- 未做：`logout` 的必填约束（请求体本来就是尽力而为）、`batchRemove` 空列表语义（#156）、客户端配置表单本地必填（#157）、接口套件 A2 增补缺失/空白负例（黑盒形状由合同测试覆盖）。
- 回归锚点：`LoginAuthContractTest`（refresh 失败全表 401，缺失/空白/无体用例与畸形 JSON 200+201 的分界）、`recognition.spec.js`（refresh 失败以 401 信封送达仍清会话，208/209）。
