# 数据范围解析成 DataScope 值对象并按查询参数应用

ADR 0053 拒绝了若依的 `${params.dataScope}` 片段拼接，定了「解析成参数进查询」的原则，并把结果写成三种互斥形态：`unrestricted` / `visibleDeptIds` / `selfOnly + userId`。多角色并集会出现「本部门 ∪ 仅本人」——一个角色给本部门、另一个给仅本人——三态表达不了。本条把结果收成一个同时携带部门可见集与本人行的值对象，并把解析器与四个查询的接法钉死。

决定：

- **值对象**：`DataScope { boolean unrestricted; Set<Long> deptIds; Long selfUserId }`，不可变，两个工厂：`unrestricted()`、`of(deptIds, selfUserId)`。
- **语义**：`unrestricted=true` 不加任何条件；`deptIds` 非空 → 部门列 `in (...)`；`selfUserId` 非空 → 再 `OR 本人列 = ?`；`deptIds` 为空且 `selfUserId` 为空 → 零行，不是全部。
- **五档映射**：`1` 全部 → `unrestricted`；`2` 自定部门 → 读 `sys_role_dept` 的部门；`3` 本部门 → 用户所在部门的 `id`；`4` 本部门及以下 → `ancestors LIKE '%,<本部门 id>,%'`（含自身）；`5` 仅本人 → `selfUserId = userId`。
- **多角色并集**：任一角色 `1` → `unrestricted`；`2/3/4` 的部门并进 `deptIds`；任一角色 `5` → 设 `selfUserId`。用户没有角色、或只有 `3/4` 但本人无部门 → 两个字段都空 → 零行。
- **解析器**：`DataScopeResolver.resolve(Long userId)` 放 auth 模块，读角色、`sys_role_dept` 与部门 `ancestors`；每次请求解析，不新增缓存（表小，失效路径沿用权限缓存）。
- **接入点只有四个**：用户列表（部门列 = `sys_user.dept_id`，本人列 = `sys_user.id`）、操作日志（部门列 = 操作人部门，本人列 = 操作人）、登录日志（同操作日志）、审批实例查询（部门列 = 发起人部门，本人列 = 发起人）。部门/岗位/菜单/角色/字典/参数/公告/监控不套；办事四种列表与审批详情不套（成员资格是更强的可见性真相）。
- **查询侧只接受参数**：MyBatis-Plus 用 wrapper 的 `in` + `or`；手写 XML 用 `#{}` 绑定 + `<foreach>`；禁止任何 `${}` 片段展开。每个查询自己回答部门列与本人列，解析器不猜业务列、不返回 SQL。
- **不缓存的例外**：`unrestricted` 之外的结果也不做请求级缓存；同一次请求内多次解析由调用方自己传递值对象。
- **前端不参与**：`/info` 不返回数据范围，客户端不做行级过滤。

考虑过的替代方案：

- **保持三种互斥形态**（否决）：多角色「本部门 + 仅本人」无法表达；硬塞进 `selfOnly` 会丢掉部门行，硬塞进 `visibleDeptIds` 会丢掉本人行。
- **MyBatis 拦截器全局改写 SQL**（否决）：隐式、难测，且会作用到不该作用的手写查询。
- **每个 service 自己 if 拼 wrapper**（否决）：五档语义会散到四个查询，各写一遍。
- **给审批列表也套数据范围**（否决）：与成员资格模型冲突，同一行两套可见性真相。
- **解析结果缓存**（否决）：角色/部门变更的失效路径会再多一条；表小，先不引入。

后果：

- 四个查询各加一个 `DataScope` 参数；用户列表与审批实例查询本波接入，操作日志/登录日志等审计模块落地时接入。
- 合同测试按五档 × 单角色/多角色并集、无部门、部门被删、空集与 `unrestricted` 补用例；用户列表与审批实例查询的空集必须返回零行而不是全部。
- ADR 0053 的「三态」按本条细化，原则（参数进查询、禁止片段拼接、四个接入点、无缓存）不变。
- `sys_dept.ancestors` 必须含自身且带包裹逗号，见 ADR 0056；部门 CRUD 迁移与解析器共用同一路径格式。
