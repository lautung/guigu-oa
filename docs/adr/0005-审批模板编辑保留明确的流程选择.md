# 审批模板编辑保留明确的流程选择，未保存内容只属于本次编辑

审批模板编辑的表单设计、流程 zip 上传与保存时序由前端编辑 module 统一管理，保留三步向导与现有后端协议，已发布模板继续只读，抄送规则编辑保持独立。上传与模板保存仍是两个动作：用户选择新 zip 后，上传成功前阻止保存；上传失败后须重试或明确恢复旧 zip，接受一次额外选择，避免悄悄保存旧流程引用而违背更换意图。

上传期间允许再选文件，以最后一次选择为准，迟到的其他上传不能替换当前选择；成功响应须包含完整的路径和流程标识，否则仍按上传失败处理。“恢复旧 zip”指恢复换包前最近一次已成功取得的包，例如 B 上传成功后再选 C，C 失败时可明确恢复 B；首次新建且尚无成功上传时没有可恢复的旧包，须完成一次成功上传才能保存。

未保存内容只属于本次打开的模板，普通离开或切换模板前确认丢弃，刷新后按原入口重新读取已保存模板或回到空白新建；不引入跨刷新恢复的未保存草稿。身份失效、失去配置权限或窗口变成手机尺寸时，直接按现有进入规则离开并丢弃未保存内容。离开后，旧上传或读取的迟到结果不得影响新的编辑页面，接受离开时放弃未保存修改的成本，保持不同编辑之间的归属明确。

提交保存后冻结本次内容并阻止重复提交，允许用户确认后离开，并说明离开不撤销已提交的保存；迟到结果不得抢导航、弹提示或影响后续页面。超时、断网及不能证明未写入的错误进入“模板保存结果待确认”，保留提交内容，暂停编辑与再次保存，并引导用户核实列表。现有新增协议没有返回模板 ID 或提供幂等保障，通用失败码也不足以证明没有写入，因此接受人工核实成本；只有确定尚未提交时才允许正常重试，保留明确认证过期后的现有至多一次认证恢复重试，重发后的超时仍按待确认处理。

待确认时提供“另开模板列表核实”和“结束本次编辑”，本次编辑不提供再次保存。另开列表保留当前提交内容，列表暂未找到不证明保存失败；结束前明确说明原保存仍可能生效，再次新建或修改可能重复创建或覆盖，结束只清理本地编辑内容，不判定原保存失败。

模板读取失败、返回空记录、已有表单内容损坏或设计器无法正确读取设计结果时，明确阻止保存并提供重试或返回；保留原数据，避免把失败降级成空内容后新建或覆盖。

正式 interface 是一次完整模板编辑，步骤推进、上传选择、可保存条件和离开行为均由编辑 module 决定，设计器与传输配合作为内部 adapter，页面与合同测试使用同一 interface。module 合同测试通过可控 adapter 验证时序，浏览器测试使用真实表单设计器与受控后端响应走完三步，证明前端配合与请求内容；服务端持久化和发布正确性继续由真实后端合同验证。

保留合法的空表单设计；流程 zip 上传成功只表示存储完成，BPMN 校验仍在发布时进行。
