# 公告全员广播带已读回执，富文本按同源白名单消毒

蓝图（[#208](https://github.com/lautung/guigu-oa/issues/208) §6）已经钉了三件事：待处理是任务通知的唯一来源；公告是全员广播 + 已读回执，顶栏铃铛只报公告未读；不做按部门/角色定向发布。本票（[#212](https://github.com/lautung/guigu-oa/issues/212)）把剩下的形状定完：发布面、展示面、富文本安全、与待处理的边界、撤回/删除后的回执。

现状是零起点：仓库没有任何公告表、接口、页面；客户端只有 form-create，没有富文本编辑器；服务端没有 HTML 消毒依赖；附件桶是私有的、下载走 15 分钟预签名 URL；CSP（ADR 0026）的 `img-src` 只放行 `'self' data: blob: https://gw.alicdn.com`；`vue/no-v-html` 在全仓是 `error`（ADR 0028 的守卫）。公告是第一个「后台发布、全员读取、富文本渲染」的独立面，所以它的每一层都要显式回答。

决定：

- **领域边界**：公告是全员广播的通知，带已读回执，不是待办。发布面在后台（系统管理 > 通知公告），展示面是顶栏铃铛、公告详情与「全部公告」；铃铛只报公告未读，待处理列表仍是审批任务通知的唯一来源。**不做**定向发布、登录弹窗、定时发布、站内信、待办铃铛。
- **状态机**：`草稿(0) → 已发布(1) → 已撤回(2)`。发布是显式的按钮动作；已发布允许继续改标题/正文（保留同一 id，不回滚已读回执），撤回后仍可再发布；再次发布刷新 `publish_time`。删除是软删（`is_deleted`），任意状态都能删，删除等价于隐式撤回；已删公告对读侧不可见。撤回与删除都不物理清除已读回执。
- **类型**：固定枚举 `1=通知 / 2=公告`，不建字典。两种值的视觉处理不同（通知偏提示、公告偏正式），产品没有第三种值的需求；标签由前端一份常量渲染，等真需要可配置再加字典迁移。
- **权限**：发布管理页挂在 `系统管理` 下，菜单路径 `notice`，页面授予走 ADR 0052；按钮点 `system:notice:query / add / edit / remove / publish`，`publish` 同时管发布与撤回（广播动作与改草稿不是同一风险等级）。铃铛、未读计数、详情与「全部公告」是内置读面：登录即有，不设页面授予，也不吃数据范围（ADR 0053 已把公告列入不套范围的配置面）。`super_admin`（当前种子为 `config_admin`）默认全授。
- **发布人**：发布时把发布人的 id 与姓名快照写进公告行，不在读时 join `sys_user`；管理员改名不重写历史公告。
- **展示面**：
  - 顶栏铃铛弹层列出最近 5 条未读，点条目进详情；底部「查看全部」进内置的「全部公告」页。未读角标来自计数接口，超过 99 显示 `99+`。
  - 拉取时机：登录成功后立即拉一次；此后每 60 秒轮询一次；`window` 重新聚焦时补拉。不做 SSE/WebSocket。
  - 「全部公告」是内置路由，两个 tab「全部 / 未读」，按 `publish_time DESC, id DESC` 分页；行显示类型标签、标题、发布人、发布时间、读/未读标记；点行进详情。列表不返回正文。
  - 详情是内置路由，显示类型、标题、发布人、发布时间与正文；进入成功后自动写已读回执。
- **已读回执**：打开详情即写，幂等；唯一键 `(notice_id, user_id)`，重复打开不产生第二行。**不做**「我已知晓」按钮、不做全部已读、不做读者名单或已读人数统计。已读只驱动未读角标，不构成待办。撤回或删除后回执保留：重新发布时此前读过的人仍是已读；公告内容被编辑也不重置回执。
- **撤回/删除后的读侧**：已撤回与已删除的公告立即从铃铛、「全部公告」与详情消失（详情按不存在处理），无论此前是否读过。管理端仍能看到已撤回与软删前的行（按状态筛选），但删除后只有 DB 历史，不提供恢复界面。
- **富文本编辑器**：Quill 2，包一层本地组件。工具栏只开标题（h1–h4）、粗体、斜体、下划线、删除线、有序/无序列表、引用、代码块、链接、图片、清除格式；不开字体颜色/字号/背景/对齐/表格/视频。粘贴内容同样进白名单。
- **服务端消毒**：写入时用 jsoup `Safelist` 消毒一次，库里存的就是干净 HTML；读取不再二次消毒（唯一写入路径在 service，二次消毒只增加成本与不确定性）。允许标签 `p br h1 h2 h3 h4 strong em u s blockquote ol ul li pre code a img`；属性只留 `a[href,title,target,rel]` 与 `img[src,alt,title]`；`style/class/id/on*` 全剥。链接协议只收 `http/https/mailto`，落库前强制 `target="_blank"` 与 `rel="noopener noreferrer"`；图片 `src` 只接受同源路径 `/admin/notices/images/{id}`，外链图、`data:`、SVG 一律剥掉。不采用客户端 DOMPurify：服务端是权威，客户端多一套白名单只会多一个绕过面。
- **唯一 `v-html` 渲染面**：新增 `src/notice/NoticeContent.vue` 作为公告正文的唯一渲染点；`vue/no-v-html` 仍对全仓 `error`，只对这一个文件开例外，并用一条守卫检查断言没有第二处 `v-html`。ADR 0028 不推翻：审批表单值仍只按文本呈现，公告正文是经过服务端白名单消毒的独立渲染面。
- **图片**：上传走服务端转存，不经浏览器直传：`POST /admin/system/notices/images` 收 multipart，单张上限 5 MB，只收 jpeg/png/gif/webp（同时看 Content-Type 与文件头魔数，拒绝 SVG）；对象放进**现有私有附件桶**的 `notices/` 前缀，不新增桶、不改桶策略。元数据表 `oa_notice_image`（`notice_id` 可空、上传人、对象键、content-type、size）。读侧 `GET /admin/notices/images/{id}` 要求登录，只允许读「已绑定已发布公告」的图片，或「尚未绑定且请求者就是上传人」的图片；响应带存储的 content-type 与 `X-Content-Type-Options: nosniff`，不提供 SVG。CSP `img-src 'self'` 保持不变。
- **图片生命周期**：保存/更新公告时按正文里出现的图片 URL 重算绑定：新出现的绑到本公告，已移除的解除绑定；未绑定的图片 24 小时后由 `@Scheduled` 清理（复用附件的 pending TTL 形状，每小时跑一次），删公告时删除其绑定图片的对象与行。这样「删公告清对象」与「孤儿清理」两件事都可测。
- **长度**：标题 `VARCHAR(100)`、DTO `@Size(max=100)`；正文 `MEDIUMTEXT`、DTO `@Size(max=100000)`（字符数，图片只存 URL）。列表接口永不返回正文。
- **接口面**：
  - 读侧（内置）：`GET /admin/notices/feed`（分页 + `unreadOnly`）、`GET /admin/notices/unread`（弹层前 5 条）、`GET /admin/notices/unread-count`、`GET /admin/notices/{id}`、`POST /admin/notices/{id}/read`、`GET /admin/notices/images/{id}`。
  - 管理侧（后台页）：`GET /admin/system/notices`（分页，按标题/类型/状态筛选）、`POST /admin/system/notices`、`PUT /admin/system/notices/{id}`、`DELETE /admin/system/notices/{id}`、`POST /admin/system/notices/{id}/publish`、`POST /admin/system/notices/{id}/withdraw`、`POST /admin/system/notices/images`。
- **服务端归属**：新建 `lautung-oa-notice` 垂直切片（`controller/service/mapper`），实体进 `lautung-oa-model` 的 `model/notice`，DTO 进 `vo/notice`；只依赖 `common/framework/security/model`，ArchUnit 增加 `Notice` 层。不塞进 `lautung-oa-auth`：auth 的职责是认证授权，公告不碰它；未来部门/字典/日志各自成模块时也不会把 auth 撑成名不副实的杂物间。
- **客户端归属**：新增 `src/notice/` 模块拥有读列表（复用 `createListRead`/`createListPage`）、未读轮询、API 与正文渲染组件；铃铛由外壳的 `TopBar` 接入。发布管理页有未保存修改时用离开确认拦截（dirty 才拦），保存草稿或发布成功后解除拦截；不做 localStorage 自动存档。
- **保留期**：不做自动清理/归档。回执与公告行按自用规模长期保留；软删公告只有 DB 历史，已读回执保留但不参与任何读面。

考虑过的替代方案：

- **第一版不做图片**：最省事，但公告最常见的用法是贴截图，纯文本会把需求挤回“发审批附件”，体验断层。
- **图片直传 MinIO + 公开读桶 + CSP `CSP_IMG_SRC`**：能复用预签名上传，但要把私有桶开成公开读（附件权限面一起被削），CSP 还要多一个环境变量与安全断言；同源转存的成本只是几十行文件缝。
- **图片 base64 内联**：`data:` 已被 CSP 放行，零服务端改动；但公告行会膨胀到 MB 级，列表/详情 payload 与备份都跟着遭殃，正文长度约束形同虚设。
- **Markdown 代替富文本**：渲染面一样要白名单，还和若依的编辑器范式不一致，用户写公告还得学语法。
- **类型走字典**：收益是改文案不发版，代价是公告模块多一条启动依赖与缓存失效面；产品只要两种值，先不付这笔。
- **两态「正常/停用」**：保存即广播，编辑中的半成品会直接推到全员；草稿态是发布面的必要条件。
- **打开详情不写、点「我已知晓」才写**：把广播变成了用户的待办，和 GLOSSARY 的「公告不是待办」直接冲突；也制造“点过才算读过”的假勤奋。
- **登录弹未读公告模态**：打断工作，且铃铛角标已经给了足够提示。
- **管理端看已读人数/读者名单**：蓝图没有这个需求，人数对自用场景没有决策价值；真要看再加聚合。
- **客户端 DOMPurify 双重消毒**：第二套白名单、第二个依赖、第二个历史漏洞面；服务端写入消毒 + 单一渲染点 + CSP 已经三层。
- **读时再消毒**：唯一写入路径已在 service 消毒，读时再洗一遍只会把成本摊到每次打开详情，并制造“库里的和页面上的不一致”的新问题。
- **公告模块放进 auth**：auth 现在是认证授权 + 用户/角色/菜单，公告不碰它；独立模块让依赖边保持单向，符合 #195 的垂直切片约定。
- **删除时连回执一起删**：回执只服务未读数，用户读过的事实不需要被抹掉；级联删还要跨两张表做补偿。

后果：

- 新增 Maven 模块 `lautung-oa-notice`、三张表（`oa_notice` / `oa_notice_read` / `oa_notice_image`）、一条 Flyway 迁移；`lautung-oa-server` 增加模块依赖，`ArchitectureTest` 增加 `Notice` 层。迁移号取当时下一个空号；审计票已占 V110，预计 V111。
- 新增 jsoup 依赖（仅 notice 模块）与 Quill 2 依赖（客户端）。
- `vue/no-v-html` 的例外只开 `NoticeContent.vue`；需要一条脚本/测试守卫“全仓只有这一处 v-html”，否则例外会静默扩散。
- 图片经服务端转发，公告图片的带宽落在应用上；自用规模可接受，对象仍在私有桶。
- 多一个 `@Scheduled` 清理任务（与附件同形状），需要测试可注入时钟或绕过调度直接调方法。
- 安全套件新增公告 XSS 用例（存储型载荷 → 页面不执行脚本、CSP 零违规）与图片 content-type 拒绝用例；被动基线用例数增长，按 ADR 0030 的常态化跑法纳入。
- `GLOSSARY.md` 增加「已读回执」，并把公告的状态与展示面写进「公告」词条。
- 菜单与按钮点 seed 与 #210 的菜单 seed 对齐；若 #210 先落地，本模块只补自己的 `system:notice:*` 行，不重写 seed 机制。
- 演示公告不随本票造：演示与种子数据是地图上的独立雾区，届时由 demo seeder 票统一补。
