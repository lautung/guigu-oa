# 组织可作审批人来源，解析结果写进发布冻结

ADR 0051 曾把「部门/岗位不进审批链」定成边界，理由是改成 `candidateGroups` 会牵动成员资格证据、待处理读、认领动作与写侧，等于重做审批核心的一块。地图 #267 把小团队真跑（3–30 人）定为硬判据：审批链全靠 BPMN 写死用户名，在人员流动、请假代理与「部门负责人审批」的日常诉求下维护不动。这条边界重开。

决定：

- 审批人来源扩成四类：**BPMN 写死的用户名、部门负责人、角色、岗位**。解析顺序、多来源并存时的优先级、与写死用户名的共存规则由审批深度票（#271）定。
- `sys_dept.leader` 从姓名 `VARCHAR(50)` 升级为对 `sys_user` 的引用；展示名走 join，不再把姓名当身份。
- 解析结果必须写进**发布冻结的 zip**：审批人以表达式或监听器表达，解析规则随模板发布一起绑定，发布证据（ADR 0003/0046）覆盖这批产物。运行期不得读「当前模板」二次解释已发布流程——同一份已发布模板在任何时候的审批人解析必须可复现。
- 解析不到人时的降级必须**显式**（拒绝发布、发起失败、转管理员等），不得静默生成无人任务；具体规则由 #271 定。
- 成员资格 gate（ADR 0011）的输入从「assignee 字符串」扩成「解析后的用户集合」；展示与动作仍从同一份证据派生。
- 部门负责人只认启用用户；停用或已删除账号不能成为解析结果。

考虑过的替代方案：

- **`candidateGroups` + Flowable IDM**：需要 IDM 组体系，而本仓的角色/岗位/部门在 `sys_*` 表里，为审批再养一套组等于两套组织真相；研究 #269 已确认本仓没有 IDM。
- **运行期动态指派（监听器读当前组织）**：发布证据失效，同一份模板在不同时间可发起性与实际审批人都会变，恢复与核验无从判定。
- **写死用户名 + 管理员定期改模板**：已发布模板不可改（ADR 0003），人员一变动只能重发新版，模板版本随人员流动膨胀。

后果：

- ADR 0051 的组织模型条目修订；GLOSSARY 的「部门」「岗位」从「不参与审批任务分配」改为「可作审批人来源」。
- ADR 0003/0011/0046 需修订，由 W1 承接；发布证据的 sha256 覆盖范围要扩到解析产物。
- 部门负责人引用迁移与审批人解析器是多票共用的底座，先于请假/调岗/报销单的模板配置落地。

**2026-11-06 补充（#271）**：解析顺序、降级与规则载体已定——每节点单选一种来源、节点规则覆盖 BPMN assignee、规则随发布产物冻结、任务创建时按当前组织解析、解析不到显式失败、多人来源按候选认领。见 ADR 0069。

Related: ADR 0051（边界被重开）；ADR 0003/0011/0046（需修订）；ADR 0001（抄送规则不进 BPMN，不受影响）；issue #267/#268/#271/#269。
