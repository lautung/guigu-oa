# 泛 OA 后台产品蓝图

> 来源：[地图 #206](https://github.com/lautung/guigu-oa/issues/206) 的蓝图票 [#208](https://github.com/lautung/guigu-oa/issues/208)，事实输入是研究票 [#207](https://github.com/lautung/guigu-oa/issues/207)。本文件是地图的终点产物，后续票以它为裁决基准。

## 1. 定位与边界

云尚办公是**桌面优先的泛 OA 后台**。审批是其中一个模块，围绕它长出系统管理、组织、审计、公告、监控与工具。长期自用、无期限、按兴趣推进；功能清单与交互范式参照若依分离版 Vue3，代码一律自研。

形态：

- 桌面优先：多标签页 + 混合导航（顶部一级、左侧二级）+ 工作台落点。
- 手机全面响应式：所有页面可打开，审批完整可用；表单设计器、流程上传、授权树、图标选择这类重交互页同样可编辑，只在顶栏提示「建议桌面」。不做只读墙。
- 撤销「统一客户端」约束：不再要求办事必须手机完成；不再有「配置页占用」与手机回落；不再用办事/配置两组限定内容密度。

明确不做：

- 不搬若依代码或整包前端。
- 不重做 Flowable 审批核心。
- 不做微信/公众号/小程序形态。
- 不做在线代码生成器：与手写 module/ADR 约定冲突（ADR 0062）。
- 不做多数据源：单库是审批双写事务的前提（ADR 0012/0062）。
- 不引 Druid 控制台：数据监控扩现有页，不新增连接池实现（ADR 0062）。
- 不做硬编码超级管理员。
- 本轮不让部门/岗位进入审批链。

注册页与界面国际化原先在同一清单里，2026-11-04 对照若依后重裁为正向能力（P1/P2，ADR 0062）；代码生成、多数据源、Druid 控制台维持不做。

## 3. 权限模型

### 3.1 三层

1. **页面授予**：角色被授予的后台页面（目录不算）。至少一个页面才构成后台权限。
2. **按钮点**：页面内的动作授权，挂在页面上；不单独构成后台权限。
3. **数据范围**：角色上的一档业务数据可见范围，见第 4 节。

三层只作用于后台。办事组内置、登录即有，不参与授权；审批可见性仍由成员资格（申请人/当前处理人/历史处理人/抄送人）决定，不套数据范围。多角色并集，用户没有直接授权。

### 3.2 菜单模型

- 继续用 `sys_menu` 一张表：`type` 0 目录 / 1 页面 / 2 按钮；按钮行带 `perms` 与 `parent_id`，挂在页面上。授权树、授予闭包、`/info` 都从这一张表出。
- 隐藏页（模板设置、分配角色）跟可见父级同一条授予；只授隐藏页而父级未授时不成立。
- 工作台与办事组不由 `sys_menu` 表达（内置）；后台目录/页面/按钮由 `sys_menu` 表达。
- 菜单管理只维护后台菜单；办事组不可增删。

### 3.3 判定顺序与拒绝形状

认证（401 + 208/209）→ 静态形状校验（200 + 201）→ 页面授予（200 + 205）→ 按钮点（200 + 205）→ service。

- 校验先于授权沿用 ADR 0034；未授权 + 畸形体仍是 201。
- 页面授予与按钮点在同一方法级 gate 内判定，顺序是先页面后按钮。
- 前端按钮语义是「无权限移除 DOM」（与若依 `v-hasPermi` 一致），不是只置灰。
- refresh 失败仍按认证家族由控制器写 401（ADR 0037），不进入这套 gate。

### 3.4 管理员

- 不硬编码：没有 `user_id == 1` 或 `role_key == 'admin'` 旁路。
- 种子角色 `super_admin` 被授予全部页面/按钮点，`data_scope = 1`（全部），再赋给种子账号。
- 新增菜单必须显式授予角色，管理员才看得见；管理员也走同一套 gate。

## 4. 数据范围

- 五档：1 全部 / 2 自定部门 / 3 本部门 / 4 本部门及以下 / 5 仅本人。多角色按并集合并；`super_admin` 用「全部」，不做身份旁路。
- 作用面只有四个查询：**用户列表、操作日志、登录日志、审批实例查询（按发起人部门）**。
- 不作用于：部门/岗位/菜单/角色/字典/参数/公告/监控这些组织自身配置；也不作用于办事四种列表与审批详情（成员资格已经是更强的可见性真相）。
- 实现原则：解析成「`unrestricted` / `visibleDeptIds` / `selfOnly + userId`」值对象，作为参数进查询。MyBatis-Plus 用 wrapper 的 `in`；手写 XML 用 `#{}` 绑定 + `<foreach>`。**禁止** `${params.dataScope}` 一类的 SQL 片段展开。
- 每个查询自己回答「本人列」是哪一列（用户 = id，日志 = 操作人，审批 = 发起人），解析器不猜业务列。
- 「自定」只来自 `sys_role_dept`；「本部门及以下」用部门 `ancestors` 前缀匹配；部门被删/停用时按当前树解析。
- 解析不出任何可见部门且不是「仅本人」时返回空集，不是全部；每次请求解析，不新增缓存（表小，失效沿用权限缓存）。

## 5. 组织模型

- **部门**：树 + 祖级路径；用户归属一个部门；是数据范围的边界，不是审批环节。
- **岗位**：用户的职务标签，可多选；不产生授权，不参与审批任务分配。
- **角色**：权限包（页面 + 按钮点 + 数据范围），可跨部门授予。
- **用户**：单部门、多角色、多岗位；有后台权限不使任何人变成另一种用户。
- **审批链**：继续由 BPMN 指定用户名。改 `candidateGroups` 会牵动成员资格证据、待处理读、认领动作与写侧，本轮不做；真要做单独立票。

## 6. 通知口径

- **待处理**是任务通知的唯一来源；不另做站内信、待办铃铛。
- **公告**是全员广播 + 已读回执：发布面在后台，展示面是顶栏铃铛与公告详情。铃铛只报公告未读。
- 不做按部门/角色定向发布（若依也没有）。
- 公告富文本在服务端按白名单消毒后渲染；这是独立渲染面，不推翻 ADR 0028（审批表单值只按文本）。

## 7. 外壳与导航

- **多标签页**：工作台固定；可关闭当前/其他/全部标签；标签只存路径与标题，不做组件缓存——列表页每次激活重读，避免与 ADR 0009/0018 的读状态、`release` 语义打架。
- **混合导航**：顶部一级（工作台/办事/系统管理/系统监控/系统工具），左侧二级。
- **登录落点**：工作台。首卡显示待处理数与近期审批量，直达待处理/发起；不按权限分流，也不落静态介绍页。
- **手机**：标签栏隐藏，侧栏收进抽屉，表格横向滚动，表单单列；重交互页可编辑 + 顶栏提示。
- **顶栏**：面包屑、侧栏折叠、全屏、公告铃铛（P1）、用户菜单（个人中心/锁屏/退出）。暗色模式与全局尺寸留原型票定。

## 9. 未做与否决的方案

- **保留统一客户端与手机回落**：每个新后台页都要背一套 surface 判定，桌面后台体感也立不起来。
- **手机只保留审批**：与选定的全面响应式相反；只读墙会让手机上连公告都改不了。
- **纯单页无标签**：失去后台最核心的桌面范式，与参照若依的目标不符。
- **按权限分流登录落点**：两套落点行为，文案与测试都分叉。
- **只做页面级授权**：日志清空、用户重置密码、在线用户强退这类破坏性动作无法按角色区分。
- **独立 `sys_permission` 表**：授权树、闭包、`/info` 要拼两张表，父子关系再表达一次。
- **硬编码超级管理员**：ADR 0013 已把种子例外拿掉；旁路让授权 bug 在管理员身上永远看不见，也让「全部」数据范围失去意义。
- **`${params.dataScope}` 片段拼接**：把授权值变成 SQL 文本，注入面、可测性与方言绑定都跟着走。
- **Quartz + 任意调用串**：为自用后台引入调度器与反射入口，收益不匹配；用 TaskScheduler + DB cron。
- **在线代码生成器**：模板要跟本仓 module/ADR/ArchUnit/合同测试约定持续维护，生成完仍要人改；要省脚手架就做离线脚本，单独立票（ADR 0062）。
- **多数据源（业务分库 / 读写分离）**：分库跨库事务会推翻审批双写的单库补偿设计；单实例单库下读写分离只增加路由层与一致性风险（ADR 0012/0062）。
- **Druid 控制台**：为一个只读面板新引连接池与登录/session/IP 白名单三件安全事；现有数据监控页扩统计即可（ADR 0062）。
- **全栈 i18n**：DB 业务名要加 key 列并改菜单管理，服务端消息与校验文案全部改造，成本与收益不成比例；只做客户端框架（ADR 0062）。
- **注册后自动登录**：绕过登录日志与失败计数，审计面出现暗区（ADR 0062）。
- **列表页 keep-alive**：与 `release()`/latest-wins 的读生命周期冲突；标签只存路径。

## 11. 落地波次

- **第 0 波（本票）**：蓝图 + GLOSSARY 重写 + ADR 0051–0053。
- **第 1 波（P0）**：外壳原型 → 权限底座（菜单/角色/用户/部门/岗位 + 按钮点 + `/info` + gate）→ 外壳实现 → 字典/参数 → 操作日志/登录日志 → 审批模块迁入。
- **第 2 波（P1）**：公告、在线用户、服务/缓存监控、个人中心、锁屏、接口文档、角色分配用户。
- **第 3 波（P2）**：数据监控、定时任务（表单构建不设页面，已由「审批设置 → 模板设置」承载，ADR 0061）。

第 1–3 波实际落地时，部门/岗位/字典/参数、个人中心、锁屏、角色分配用户未随波完成；2026-11-04 对照若依后按 ADR 0062 重排为第 4–9 波（票挂 #206）：

- **第 4 波（组织基座）**：部门管理、岗位管理、用户页部门树与岗位分配、重置密码。
- **第 5 波（配置基座）**：字典管理（含 `DictTag`/`useDict` 与首批枚举迁移）、参数设置（首批只种注册开关）。
- **第 6 波（账号自助）**：注册页（依赖参数开关）、个人中心（取代「基本信息」）、锁屏。
- **第 7 波（权限加料）**：角色分配用户（角色侧成员维护）。
- **第 8 波（观感与观测）**：i18n 框架（外壳/登录/通用组件/新页面）、数据监控统计。
- **第 9 波（导入导出）**：用户导出先落，导入后置并单列部分成功语义。

硬依赖：参数先于注册；部门先于用户页部门树；字典先于任何按字典渲染标签的页面；其余可并行。
