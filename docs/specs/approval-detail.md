# 审批详情读取与处理时序

状态：已实施（2026-10-18）；本文保留确认后的行为合同，实施及验收记录见末节。

跟踪 Issue：[Spec: 审批详情读取、处理与离开时序 #96](https://github.com/lautung/guigu-oa/issues/96)。Issue 按完整规格模板发布，包含 50 条用户故事与本次确认的测试 seam。

## 范围与既有约束

深化统一客户端现有审批详情 module，将读取、处理、失败恢复和离开时序收进同一 interface。待处理、已处理、已发起、抄送我的与配置查询仍指向同一次审批，保留各自展示视角与返回位置。

后端接口、业务权限、审批步骤和附件登记规则保持现有约定。通过或拒绝只在待处理入口、具有当前处理资格时可用；其他入口不因接口返回可处理或存在待确认记录而获得处理入口。附件补传资格继续由原有附件权限判定。

领域含义以 [GLOSSARY.md](../../GLOSSARY.md) 为准。结果不确定时采用人工核实的取舍见 [ADR-0004](../adr/0004-审批处理结果待确认且离开不撤销.md)。

## Module 的职责

- 打开时确定本次进入结果、审批、待处理任务及入口视角，后续响应不重新读取可变路由来猜测归属。
- 对外提供打开详情、观察页面状态、重新读取、通过或拒绝、明确结束待确认记录、释放本次打开的能力。页面负责呈现与发出意图，读取顺序、处理中状态、提示和跳转资格由 module 统一决定。
- 同一审批换任务、换入口，或离开后再次返回，均须重新核实当前详情。旧打开的响应不能覆盖新目标，也不能因为地址再次相同就重新取得提示或导航资格。
- 生产 HTTP adapter 与可控延迟、失败的测试 adapter 经过同一 seam。展示与请求组装函数可作为 implementation 内部细节，测试覆盖完整的读取、处理与离开配合。
- 身份失效、停用和认证恢复继续使用现有认出能力；详情 module 接管本次操作的普通错误提示，避免全局提示与页面提示重复。

## 读取与返回

| 场景 | 目标行为 |
| --- | --- |
| 首次进入或切换审批 | 清空前一目标的内容，读取新目标；尚未成功读取时不可处理。 |
| 切换任务或入口视角 | 按新目标核实详情、处理资格和返回位置；忽略旧读取的迟到结果。 |
| 同一详情手动刷新失败 | 保留最后成功读取的内容，标记“详情尚未更新”，禁用通过与拒绝，并提供手动重试。 |
| 首次读取失败 | 显示错误和手动重试入口；仍能返回原入口列表。 |
| 明确无权读取 | 清除已读详情，显示原因并提供返回入口。 |
| 用户离开 | 释放本次打开的呈现资格，旧结果不再提示、导航或修改后续页面。 |

读取失败不自动循环重试；重新打开或用户主动刷新时重新读取当前详情，不把旧展示内容当作实时结果。

## 处理与结果

| 场景 | 目标行为 |
| --- | --- |
| 发出通过或拒绝 | 固定本次审批、任务及所选动作；等待期间禁用两个处理按钮，重复点击不追加请求。 |
| 等待结果时离开 | 允许直接离开，不撤销已提交处理。迟到结果仍只归原操作。 |
| 明确成功且仍在本次打开 | 自动进入已处理。 |
| 明确成功但已离开或换身份 | 不抢导航、不提示、不修改后续页面。可靠结果可以更新原操作记录的内部结论。 |
| 明确拒绝或处理资格发生变化 | 留在当前详情说明原因，允许手动刷新或返回待处理；刷新后按最新资格展示。 |
| 超时、断网或其他无法确认结果的响应 | 进入处理结果待确认，不自动重发，也不按明确失败解锁再次提交。 |
| 审批请求明确收到业务 208 | 维持现有认证恢复；恢复成功后至多重试一次，因为该请求尚未进入审批处理。认证恢复失败不重放。 |

生产 adapter 按实际响应合同区分明确成功、明确拒绝与结果不确定，不能把所有 Promise 拒绝、HTTP 错误或无法解析的响应一律归为明确失败。任务已不存在或无权访问，也不能被解释成此前某次处理已经成功。

## 处理结果待确认的恢复

- 记录按本次进入结果及待处理任务隔离，并保留审批与所选动作的关联；离开、返回或刷新不丢失。记录只保存恢复所需的最小信息，完整审批内容重新读取。
- 提供刷新详情、查看已处理和返回待处理的核实路径。刷新读到的整体状态、处理资格或列表变化，均不自动解除原任务的待确认记录。
- 用户核实后明确结束本次记录；若仍需处理，从最新待处理重新进入并主动选择。结束记录或再次看到待处理任务，都不表示原请求失败。
- 同一审批的另一个任务、已处理或其他只读入口，不得解除原任务记录，也不得因此获得处理按钮。
- 新登录不展示或继续旧进入结果的处理记录；先前用户的迟到结果不能影响当前用户。
- 恢复记录不可写或不可读时明确显示故障，不能静默丢弃记录后发出新的处理请求。

## 附件协调

附件仍独立登记在同一次审批上，补传与下载经过原有附件 module。详情 module 协调附件操作与处理动作的时序，页面无需自行拼接相互独立的 busy 标记。

- 一批补传从开始到登记结束都阻止通过或拒绝，包括文件之间的间隙；不排队自动提交，上传完成后需要用户重新点击处理。
- 从处理请求提交开始，直到得到明确结论或用户结束待确认记录，暂停新增补传；附件读取与下载继续可用。
- 附件读取失败提供重试，不把它视为审批处理失败或处理成功；正在读取、下载本身不阻止处理。
- 切换审批或身份后，旧附件结果不得登记到新审批、写入新页面或发出旧页面提示；已经发生的对象存储写入与服务端登记仍依原有规则处理。

## 验收

通过 module 的公开 interface 与可控 adapter 验证：

1. 读取 A 未结束就打开 B；A 后来的成功与失败均不改变 B 的内容、加载状态、提示和导航。
2. 同审批切换任务或入口，以及离开后再次打开相同地址，旧打开不重新取得呈现资格；五种入口保留展示视角、只读约束与返回位置。
3. 首次读取失败、同页刷新失败、手动重试成功与明确失去读取权限的展示和处理资格符合上述规则。
4. 重复点击、同时点击通过和拒绝，仅产生一次本地提交；提交固定正确的审批、任务及动作。
5. 明确成功只在原打开仍有效时进入已处理；处理未返回时离开、换身份或再次进入，迟到结果不抢导航或提示。
6. 明确拒绝留在当前审批；超时、断网及不明响应保留待确认，跨释放、重新打开与刷新恢复后不自动重发。
7. 刷新、任务消失、无权访问、另一个任务或已处理列表出现，均不能自动宣告原处理成功或失败；人工结束记录后从最新待处理继续。
8. 明确业务 208 后至多一次认证恢复重试；认证失败、网络故障与刷新失败不触发额外业务重放。
9. 补传整批在途时阻止处理且不排队；处理在途及待确认期间暂停新增补传，附件读取和下载可用；旧附件回调不影响新审批或新用户。
10. 待确认记录不可写、损坏或不可恢复时有明确故障状态，不能退化为静默清空后继续提交。

替换被新 interface 验收覆盖的浅层 helper 测试，保留仍有独立合同价值的测试。桌面与手机浏览器覆盖主要成功路径、切换与离开、待确认恢复及附件互斥；受控 API 和对象存储响应只证明客户端交互与请求组装，后端持久化与真实 Flowable 行为仍由相应后端合同或真实运行验证。

## 实施及验收记录（2026-10-18）

- `src/work/approval-detail.ts` 提供统一公开 interface，页面和测试均通过打开、观察状态、刷新、处理、核实结束与释放使用详情能力；HTTP 与浏览器存储接线在 `src/work/approval-detail-http.ts`。
- 最小恢复记录按进入结果及原任务保存到浏览器本地存储；开始提交前先写入记录，明确响应只结束对应操作，通信故障不自动重放。只有原待处理任务可以人工结束记录，结束后须从最新待处理重新进入。
- 详情 module 同时协调附件读取、下载及整批补传；处理中与待确认暂停新增补传，页面不自行拼接多个 busy 标记。原请求使用固定身份上下文，旧附件结果不写入新审批或新身份。
- 已以 red → green 逐条完成读取归属、刷新失败与权限变化、处理去重、持久恢复、附件互斥、生产 HTTP 208 恢复和恢复记录故障的竖切；原浅层详情 helper 测试迁移到公开 interface。
- 前端 lint、类型检查、完整单元测试（19 个文件、251 例）、格式检查、生产构建通过。lint 保留现有两处 `v-html` 警告；构建仍有既有深度选择器弃用与 chunk 体积提示。运行环境为 Node 24.18.1，与项目声明 `^22.18.0` 存在版本差异。
- `tests/e2e/approval-detail.spec.ts` 与 `tests/e2e/workflow-smoke.spec.ts` 在桌面 Chromium（1280×900）和手机 Chromium（390×844）合计 14 例通过，覆盖通信故障后刷新恢复、人工核实结束、处理中离开、相同地址重开、A/B 读取切换、附件整批互斥、只读返回与通过/拒绝成功路径。当前无 Browser 插件，使用仓库 Playwright；`pageerror` 检查无应用运行时错误，列表中的既有 Element Plus `type=text` 弃用提示仍存在。
- 浏览器测试使用受控 API 和对象存储响应，仅证明客户端交互、结果归属和请求组装；本次未运行真实后端持久化、对象存储登记或 Flowable 全链路，也没有改动后端接口、数据库或业务权限。
