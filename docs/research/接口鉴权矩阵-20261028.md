### 1.3 JWT 与失效语义

| 事实 | 依据 |
|---|---|
| token 放在自定义请求头 `token`，不是 `Authorization: Bearer` | `TokenAuthenticationFilter.java:77-79`；`SpringDocConfig.java:21-26` |
| access token 2 小时；refresh token 7 天 | `JwtHelper.java:17-18` |
| token claims：`subject=AUTH-USER`、`userId`、`username`、`tokenType=access/refresh` | `JwtHelper.java:20-22,68-77` |
| 读取时校验 subject 与 `tokenType`；access 不能当 refresh，refresh 不能当 access | `JwtHelper.java:97-104` |
| 签名密钥至少 64 个 UTF-8 字节；生产 profile 只从 `JWT_SECRET` 取 | `JwtHelper.java:26-32`；`application-prod.yml:1-3` |
| 开发默认密钥写在 `application-dev.yml` | `application-dev.yml:37-39` |
| 每个请求重新按 username 查用户，并校验 JWT 的 `userId` 与库中 id 一致 | `TokenAuthenticationFilter.java:81-95` |
| 用户不存在 → 认证失败 208；用户停用 → 209 | `TokenAuthenticationFilter.java:86-96`；`TokenLoginFilter.java:61-63` |
| 停用判定是 `status != 0`；`status=2`、`-1` 也算启用 | `AccountStatus.java:5-8` |
| 刷新只校验 refresh 类型、userId/username 一致、未停用；不轮换 refresh，保持原 7 天到期 | `IndexController.java:87-106`；`LoginAuthContractTest.java:150-188` |
| `logout` 只返回成功，不删 Redis、不作废 JWT | `IndexController.java:79-82`；`GLOSSARY.md:43-44` |
| 没有服务端 token 黑名单/会话表；JWT 在过期前持续有效 | `JwtHelper.java` 全文无存储；`TokenAuthenticationFilter.java` 只做验签与用户状态校验 |
| 改密码不会作废已签发 JWT；删除用户会使后续请求 208（查不到用户） | `TokenAuthenticationFilter.java:86-90`（只查用户，不校验密码）；`UserDetailsServiceImpl.java:21-28` |

### 1.4 Redis 权限缓存

| 事实 | 依据 |
|---|---|
| `/info` 把该用户的按钮权限写进 Redis，key 是 username，value 是 authority JSON | `IndexController.java:109-118` |
| 角色/菜单变更后按角色成员或用户删除 Redis 缓存 | `PermissionCacheInvalidator.java:24-68,70-101` |
| `TokenAuthenticationFilter` 把 Redis 中的 authority 装进 `Authentication` | `TokenAuthenticationFilter.java:101-115` |
| 全仓没有任何 `hasAuthority` / `hasRole` / `@Secured` 消费这些 authority；唯一的授权注解是 `configurationMenuGate` | 对 `server/guigu-oa-parent` 主源码的注解扫描；`ConfigurationMenuGate.java:20-23` |
| Redis 为空或不可用时，token 校验仍通过，只是 authority 为空 | `TokenAuthenticationFilter.java:101-115` |

结论：当前 Redis 里的 authority 只影响 SecurityContext 中的权限集合，**不参与任何服务端鉴权判定**。真正的配置鉴权每次都读数据库菜单（`ConfigurationGrant.snapshot` 全量读 `sys_menu`，`ConfigurationGrant.java:42-79,303-311`）。

## 2. 配置权限 gate

### 2.1 判定方式

```java
@PreAuthorize("@configurationMenuGate.isGranted('sysUser')")
```

- `ConfigurationMenuGate.isGranted(menuPath)` 从 `LoginUserInfoHelper` 取当前 userId，再调用 `ConfigurationGrant.snapshot(userId).covers(menuPath)`（`server/guigu-oa-parent/service-oa/src/main/java/com/atguigu/auth/service/ConfigurationMenuGate.java:20-23`）。
- `GrantedConfiguration.covers` 只做**精确** `pagePaths.contains(menuPath)`（`ConfigurationGrant.java:343-345`）。
- `pagePaths` 加入的是 `sys_menu.path` 原始短路径（例如 `sysUser`、`processTemplate`），不是路由绝对路径（`ConfigurationGrant.java:57,69`）。所以注解里的 `'sysUser'` 与库里的 `path` 对应。
- 只被授予目录不算配置权限；页面必须 type=1 且自身与祖先都启用（`ConfigurationGrant.java:136-141,247-269`）。
- 隐藏页跟随可见父级：授予可见父页时，隐藏子页自动出现在 `configMenus`，并把隐藏页 path 加进 `pagePaths`；单独授予隐藏页而父页未授予时无效（`ConfigurationGrant.java:43-79,143-155`）。
- 目录与页面之外的菜单（办事、公众号、Dashboard、在线流程设计器、部门/岗位/日志）不算配置菜单（`ConfigurationGrant.java:27-30,271-283`）。
- 拒绝形状：方法级 `AccessDeniedException` 由 `GlobalExceptionHandler` 转成 HTTP 200 + 业务码 **205**（`GlobalExceptionHandler.java:41-50`；`ConfigurationRouteAuthorizationContractTest.java:145-151`）。

### 2.2 覆盖范围

35 个配置端点全部带 gate；`ConfigurationRouteAuthorizationContractTest` 在启动时遍历 `RequestMappingHandlerMapping`，要求六个配置 Controller 的每个 handler 都有对应 gate，且顺序与预期完全一致（`ConfigurationRouteAuthorizationContractTest.java:47-70,93-110`）。办事 Controller（`ProcessController`）与认出 Controller（`IndexController`）明确不带配置 gate（同测试 `112-132`）。

### 2.3 页面级授予的实际写入能力

配置权限是**页面级**，没有按钮/动作级权限（`GLOSSARY.md:19-21`；ADR 0013「页面级授予覆盖该页全部读写」`docs/adr/0013-配置路由按菜单授予统一gate且种子账号不再例外.md`）。因此：

| 授予页 | 同时获得的高影响写操作 | 依据 |
|---|---|---|
| `sysUser` | 读取/新增/修改/删除用户；给任意用户分配任意角色（含 `config_admin`） | `SysUserController.java:39-123`；`SysRoleController.java:35-50`；`SysRoleServiceImpl.java:126-149` |
| `sysRole` | 角色增删改；给任意角色授予任意「可授予配置菜单」，包括自己所属角色 | `SysRoleController.java:61-168`；`SysMenuController.java:33-47`；`SysMenuServiceImpl.java:127-161` |
| `sysMenu` | 维护配置菜单（受保护路径有额外限制） | `SysMenuController.java:50-81`；`SysMenuServiceImpl.java:163-210` |
| `processTemplate` | 审批模板增删改、上传流程 zip、发布 | `OaProcessTemplateController.java:35-106` |
| `processType` | 审批类型增删改 | `OaProcessTypeController.java:32-79` |
| `process` | 查询所有审批实例列表 | `OaProcessController.java:36-46` |

其中 `sysUser` 与 `sysRole` 两项可以互相组合成「给自己加任意角色 / 给任意角色加任意配置页」，代码里没有反向约束（`SysRoleServiceImpl.doAssign` 直接按传入 roleId 写 `sys_user_role`，`SysMenuServiceImpl.doAssign` 只校验菜单可授予、不校验调用者是否拥有该菜单）。这是权限模型的一个结构性事实，不是某个接口的漏判。

## 4. 端点 × 鉴权矩阵

列说明：

- **token**：请求头 `token` 是否需要有效 access JWT。
- **配置 gate**：`configurationMenuGate.isGranted(...)` 的参数；`—` 表示没有配置 gate。
- **成员/归属**：是否按审批成员资格或资源 owner 限制；`无（配置页）` 表示配置页只判菜单授予，不再判单条资源归属。
- 所有行都是 HTTP 200 业务包裹；错误码见 §7。

## 7. 错误码与响应包裹

